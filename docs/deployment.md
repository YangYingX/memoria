# Windows 与 Linux 部署

可选飞书文本通道使用独立的原版 DSH 消息宿主，安装、应用身份核对和后台设置见[飞书接入说明](feishu.md)。主服务与聊天渠道分别配置；默认不启动飞书连接。

Memoria 使用 Node.js 22.16 或更新版本、npm 和 Node 内置 SQLite。Linux 启停脚本需要 Bash 4.4+ 和已挂载的 `/proc`，不依赖 Docker。请安装对应系统与 CPU 架构的 Node.js，再执行 `node --version` 确认版本；不要把 Windows 的 Node 或 `node_modules` 目录复制到 Linux。

小黑盒自主浏览另需 Playwright 的 Chromium headless shell。浏览器系统要求比纯聊天更严格，建议选择官方支持的 Windows 11 / Windows Server 2019 或更新版本，以及 Debian 12/13、Ubuntu 22.04/24.04/26.04；Linux 使用 x86-64 或 arm64。具体支持范围以 [Playwright 系统要求](https://playwright.dev/docs/intro#system-requirements)为准。

程序只监听 `127.0.0.1:3210`。本地管理后台需先设置管理员密码，模型 API、QQ 登录和云盘授权分别配置。部署程序不会自动登录这些外部账号。

后台用于配置与管理；完成 QQ 绑定后，创建人可通过私聊进行日常对话、发 TXT 收书和查询阅读进度。无需每次打开后台。

运行不需要 Codex 或其他开发工具在线。服务直接调用已配置的模型 API，自己执行调度并保存数据；关闭管理网页不会停止服务。Windows 后台启动和 Linux systemd 的具体方式见下文。

## QQ 对话额度

在“人格与设置 → QQ 接入”调整“每日智能对话尝试上限”，默认 200，范围 0–1000。QQ 私聊、群聊与主动私聊判断共用此额度，按 UTC 日期保存；处理前预留一次，处理或发送失败、主动判断选择安静也计次，不退回。主动私聊仍受自身发送和判断上限约束。

设为 0 或额度用尽后暂停新的智能处理，不发送限额提醒，也不积压消息等待补发。身份绑定和 TXT 收书命令仍可使用；未获准的消息和重复事件不扣次。后台显示今日已用与剩余，聊天中也可查询。

同一实例重启、修改配置或恢复备份不会清零本机当天已用次数；这份运行计数不随备份迁移到新实例。本机后台聊天不占 QQ 额度。每日 200 次模型请求和全平台 80 次公开发布仍分别计数；一次聊天可能使用多次模型请求，因此调高 QQ 上限不会提高模型总额度。

### 连发文字与取消

在“人格与设置 → QQ 接入”调整“连发文字等候（毫秒）”，默认 700，范围 0–1500，0 关闭合并。只合并同一发言者在同一私聊或同一群内连续发来的纯文字；每批最多 3 条、合计 8000 字符，自第一条起最多等候 1800 毫秒。不同群友、图片、文件或绑定命令会结束当前合并，群内未 @ 的消息不进入模型。同一聊天的智能回复按批次顺序处理，绑定与收书确认仍可独立返回。

每条原始消息分别去重；一批只预留一次 QQ 聊天尝试，实际模型请求仍逐次计入模型总额度。合并正文以换行分隔，原消息 ID、接收时间和正文位置保存在本机消息与经历中，随加密备份保存。模型仅获得合并条数及说明，核对原话时会标明多条合并。更正或忘记相关来源时，原有整轮对话屏蔽规则仍适用。

关闭 QQ、更改 QQ、模型或人格配置，以及修改账号绑定，会取消待处理批次，并阻止在途聊天继续生成和发送回复。已经启动的读书、书籍导入等独立任务可能仍保存结果，取消聊天不回滚已完成的资料操作。已经发起的模型请求仍计费、计次，已经在途的发送无法保证撤回，不自动重发。待处理队列仅保存在内存，进程退出或异常中断后不恢复补发；需要时请重新发送。

没有到期约定时，主动私聊开启且 DSH 可用便优先从最近七天内仍可见、尚未判断过的创建人最新私聊延续近况、兴趣或约定；没有新的私聊线索，或未启用 DSH 时，再考虑实际阅读。每个原生回合最多 4 次模型请求、5 次只读工具；阅读判断最多一次模型请求，两种随机话题与约定跟进共用每天最多 6 次判断。同一机会只选择一种话题，安静、失败或取消后不立即转为另一种。每次判断占一次 QQ 智能对话尝试，每次模型请求分别占全局额度。默认主动私聊仍关闭；原有每天最多 1 次发送、安静期、活跃时段与机会间隔继续生效。

随机话题中的同一条最新私聊、同一网页地址或同一已读书籍片段，在判断开始前记入持久去重；安静、失败和取消也不自动重试。同网址再次读取产生新条目，仍按同一来源处理。判断事件随备份保存，本机还保留独立的执行去重记录；恢复较旧备份不会重试同一来源，也不会清空本机当天已用的主动判断或发送计数。恢复仍会暂停主动私聊并清除账号绑定。新机器恢复判断前的旧备份时，无法得知后来发生的判断。

### 在聊天中约定跟进

只在已验证创建人身份的私人对话中接受当前明确的纯文字请求；群聊、其他人的请求、引用、转述和图片中文字不能安排跟进。先验证绑定创建人 QQ 并启用 QQ 接入；当前跟进只发往该绑定的 QQ 私聊。日常入口仍是聊天，后台“主动私聊”仅展示约定状态与时间，不新增操作按钮。

例如分别发送：

- “明晚20:00问问我考试情况”——使用“主动聊天时区”，也可以在消息中明确时区；时间或目标不清楚时先询问。
- “列出我的约定”——核对标题、时间和状态。
- “取消考试提醒”——目标不唯一时先说明是哪一条。
- “恢复考试提醒”——仅恢复仍有效的暂停条目，例如恢复备份后重新绑定 QQ；已取消、过期或失效的条目不能恢复。

未来时间范围为一分钟后至 366 天内，最多保留 20 条未结束约定；标题和内容存入统一记忆书架，关联当次创建人原话。每轮聊天创建、取消、恢复合计最多尝试一次，参数错误和操作失败也计次。修改或忘记关联记忆、屏蔽原话来源以及解绑账号会使原约定失效；需要新的安排时，应在聊天中重新明确提出。

主动私聊默认关闭，保存约定不会自动开启。聊天欲为 0、每日发送额度为 0，或账号、模型未就绪时保持安静。到期约定优先于随机话题，但仍受活跃时段、机会间隔、冷却、空闲和预算约束；后台的“下次随机机会”不是约定的发送时间。跟进是机会式关心，不是准点闹钟，也不保证必定发送。

每条约定最多判断 3 次，安静、生成失败或取消也计次，之后结束；到期后 24 小时截止，不补发过期约定。随机主动聊天和约定跟进合计每天最多 6 次判断，共用默认每日最多 1 次发送、QQ 智能对话额度与每日 200 次模型请求总额。DSH 可用时当次拟聊最多 4 次模型请求、5 次只读工具；没有 DSH 时使用一次模型判断。发送失败或结果未确认仍占尝试，未确认标为 `unknown`，不自动重发。

调度、身份、书架和额度由栖忆统一保存；可选原版 `dsh-speak-up` 只触发当次拟聊，不启动第二套常驻调度，也不表示完整接入其他 DSH 约定插件。结构版本 5 备份包含聊天约定；恢复会暂停未发送的有效条目并清除绑定，重新验证 QQ 后仍需在聊天中明确恢复。过期、来源失效或发送结果未确认的条目不恢复发送；同一实例保留本机当天已用计数和已发送去重，恢复旧备份不会重新获得额度。

## 代码包与数据

将 `src/`、`public/`、`scripts/`、`deploy/`、`docs/`、`package.json`、`package-lock.json`、Windows 的 `*.cmd`、许可文件和文档作为程序包。包中不包含 `data/`、`backups/`、`node_modules/`、`.env`、日志、数据库、`.pab` 备份或真实账号凭据。在目标机器的项目目录执行：

```bash
npm ci --ignore-scripts --no-fund --no-audit
npm run check
```

程序数据默认位于项目的 `data/`。Linux 脚本支持 `PERSONA_DATA_DIR` 指定独立数据目录；启动与停止时必须使用同一目录。`PERSONA_BACKUP_DIR` 指定自动备份目录。systemd 模板把两者分别设置为 `/var/lib/persona-agent` 和 `/var/lib/persona-agent-backups`，避免程序安装目录需要写权限。自动备份目录必须独立于数据目录，不能设成数据目录本身或其子目录。

## 自主浏览器安装

小黑盒自主浏览及聊天、后台中的小黑盒帖子阅读都需要浏览器二进制。QQ 聊天、识图、表情与普通 HTML 阅读可以先行使用；识图还取决于模型是否支持视觉输入。

Windows 在已安装依赖的项目目录执行：

```powershell
npm.cmd run browser:install
```

Linux 桌面或普通用户部署，可一次安装浏览器和系统依赖：

```bash
npx playwright install --with-deps chromium --only-shell
```

这条命令可能为系统软件包申请管理员权限；日常运行浏览器须使用普通用户，并保持 Chromium 沙箱开启。不要用 `--no-sandbox` 或关闭 `chromiumSandbox` 处理启动错误。systemd 专用用户的安装方式见下节。[Playwright 浏览器安装说明](https://playwright.dev/docs/browsers#install-system-dependencies)、[无界面浏览器安装选项](https://playwright.dev/docs/browsers#chromium-headless-shell)。

浏览器默认保存在当前用户的 Playwright 缓存中。自定义缓存时，安装和启动必须使用同一个 `PLAYWRIGHT_BROWSERS_PATH`，且运行用户能读取、执行其中的文件。例如 Linux：

```bash
export PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/memoria-browsers"
npm run browser:install
bash scripts/start.sh
```

Windows 可在同一 PowerShell 窗口设置 `$env:PLAYWRIGHT_BROWSERS_PATH`，再安装并执行 `.\start.cmd`；若改用双击启动，请把相同地址设置为 Windows 用户环境变量。程序不会替你更改系统环境变量。[Playwright 缓存说明](https://playwright.dev/docs/browsers#managing-browser-binaries)。

升级 Playwright 依赖后，按同样的缓存路径重新运行浏览器安装命令。若出现“浏览器无法启动”，先确认运行用户、缓存路径与 Linux 系统依赖；沙箱报错还需检查宿主机、容器或 AppArmor 对非特权用户命名空间的限制。使用普通用户和有效沙箱运行，不通过关闭沙箱继续访问网页。[Playwright 浏览不可信网站的运行建议](https://playwright.dev/docs/docker#crawling-and-scraping)。

## Windows 安装与运行

选择自己有读写权限的安装目录。安装依赖后双击 `start.cmd` 后台启动，`stop.cmd` 停止。访问 `http://127.0.0.1:3210`，使用 `data\setup-key.txt` 中的初始化码设置管理员密码。日志位于 `data\server.log` 与 `data\server.err.log`。

## Linux 安装与运行

将程序放在自己有写权限的目录，例如 `~/persona-agent`，安装依赖后运行：

```bash
bash scripts/start.sh
bash scripts/stop.sh
```

以上两条命令分别用于启动和停止，按需要单独执行。请使用 `bash` 调用。

运行日志保存在数据目录的 `server.log` 和 `server.err.log`。

使用独立数据目录时：

```bash
PERSONA_DATA_DIR="$HOME/.local/share/persona-agent" bash scripts/start.sh
PERSONA_DATA_DIR="$HOME/.local/share/persona-agent" bash scripts/stop.sh
```

初始化码位于所选数据目录的 `setup-key.txt`。日志可用 `tail -n 100 data/server.err.log` 查看。若提示 `.start.lock` 已存在，先确认没有另一个启动脚本运行，再用 `rmdir` 删除提示中的空锁目录；不要删除数据目录。无法确认 PID 文件指向谁时，先检查进程，不要直接杀进程。

## Linux systemd 长期运行

以下以 Debian/Ubuntu 为例，程序目录 `/opt/persona-agent`，专用运行用户 `persona-agent`。先把不含私密数据的代码包解压或复制到该目录，确认当前 Node 版本和安装路径：

```bash
command -v node
node --version
```

模板默认使用 `/usr/bin/node`。若实际路径不同，修改 `deploy/persona-agent.service` 中的 `ExecStart`，并同步替换下方命令中的 Node 路径。Node 必须是服务用户可访问的系统安装，不能指向个人家目录中的 nvm 路径，因为模板启用了 `ProtectHome=yes`。同样不要把程序或浏览器缓存安装在个人家目录后直接使用此模板。

新机器没有 `persona-agent` 用户时创建一次，然后在项目目录安装依赖并安装服务：

```bash
sudo useradd --system --user-group --home-dir /var/lib/persona-agent --no-create-home --shell /usr/sbin/nologin persona-agent
cd /opt/persona-agent
sudo npm ci --ignore-scripts --no-fund --no-audit
sudo chown -R root:root /opt/persona-agent
sudo chmod -R a+rX /opt/persona-agent
sudo /usr/bin/node node_modules/playwright/cli.js install-deps chromium
sudo install -d -m 0700 -o persona-agent -g persona-agent /var/cache/persona-agent-browsers
sudo -u persona-agent env PLAYWRIGHT_BROWSERS_PATH=/var/cache/persona-agent-browsers /usr/bin/node node_modules/playwright/cli.js install chromium --only-shell
sudo install -m 0644 deploy/persona-agent.service /etc/systemd/system/persona-agent.service
sudo systemd-analyze verify /etc/systemd/system/persona-agent.service
sudo systemctl daemon-reload
sudo systemctl enable --now persona-agent
sudo systemctl status persona-agent --no-pager
```

只对这个新部署、仅包含程序代码的 `/opt/persona-agent` 目录执行上述权限命令。已有数据应迁移到 `/var/lib/persona-agent`，不要将私密数据设置为所有用户可读。服务的 `StateDirectory` 会创建归 `persona-agent` 所有、权限均为 `0700` 的数据目录和独立备份目录；`CacheDirectory` 管理独立浏览器缓存。`ProtectSystem=strict` 使程序目录只读，数据、备份、浏览器缓存和隔离的临时目录保持可写。备份恢复密码与服务机凭据仍应由创建人保管。

模板设置 `PLAYWRIGHT_BROWSERS_PATH=/var/cache/persona-agent-browsers`，并保留 `NoNewPrivileges=yes`；没有禁止 Chromium 所需的用户命名空间。宿主系统仍须允许普通用户创建浏览器沙箱。可以先在项目目录用实际服务用户检查无界面浏览器启动：

```bash
sudo -u persona-agent env PLAYWRIGHT_BROWSERS_PATH=/var/cache/persona-agent-browsers /usr/bin/node --input-type=module -e "import { chromium } from 'playwright'; const browser = await chromium.launch({ headless: true, chromiumSandbox: true }); await browser.close();"
```

这只检查浏览器能否启动。服务启动后，再在后台手动发起一次小黑盒活动，核对实际结果；站点登录或验证码限制仍可能使访问失败。

查看初始化码与日志、停止和重启服务：

```bash
sudo cat /var/lib/persona-agent/setup-key.txt
sudo journalctl -u persona-agent -n 100 --no-pager
sudo systemctl stop persona-agent
sudo systemctl restart persona-agent
```

服务由 systemd 管理时使用 `systemctl`，不要再运行 `start.sh` 或 `dev.sh` 启动第二份进程。systemd 模板等待停止最多 20 秒，且关闭自动 `SIGKILL`；停止失败时先检查日志和进程再处理。升级前先导出加密备份，停止服务，更新程序文件并重新执行 `npm ci --ignore-scripts`；若 Playwright 版本变化，也以服务用户更新同一缓存内的浏览器，最后重启。

## 远程服务器访问

在自己的电脑终端建立 SSH 隧道，将以下示例中的登录名和服务器地址替换为实际值：

```bash
ssh -N -L 3210:127.0.0.1:3210 your-user@your-server
```

保持终端开启，浏览器访问 `http://127.0.0.1:3210`。服务会核验 HTTP Host，因此本地隧道端口也须使用 `3210`。如果本机已有 Memoria，占用同一端口，先停止本机实例。无需公开 `3210` 端口或修改服务监听地址。QQ 协议端推荐部署在同一机器，通过回环地址连接；Windows NapCat 不能直接通过自身的 `127.0.0.1` 连接另一台 Linux 服务器。

## 跨平台迁移

从旧实例后台导出 `.pab` 加密备份，在目标系统安装相同或兼容版本，初始化新管理员后预览并恢复。备份内容是加密的结构化 JSON，由目标系统重建 SQLite 数据，适合 Windows 与 Linux 之间迁移。恢复后需重新填写模型与平台凭据、核验账号绑定并开启外部接入；不要在程序运行中只复制单个 `.sqlite` 文件，以免遗漏 WAL 中的数据。

创建人上传的表情、QQ 收藏的表情图片、各自可用范围和删除记录随加密备份迁移；这些个人图片不进入公开源码。内置表情随程序源码分发。浏览器二进制不在备份中，须在目标系统另行安装；不要把 Windows 的浏览器缓存复制给 Linux 使用。

书籍正文、阅读位置、已保存的笔记和聊天约定也随加密备份迁移。目标系统恢复后，先核对书房和账号绑定，再按需重新开启自主读书、自主浏览、自主表达、主动私聊与自动备份。未发送的有效约定会暂停，重新绑定 QQ 后，仍需在聊天中明确恢复；不要把开启主动私聊当作恢复了所有约定。

小黑盒自主选文会按需参考最多三条未改动的公开阅读笔记，延续其中的疑问；与创建人兴趣共用一次选文判断，不新增日程或提高活动次数。使用后台配置的模型和每日 200 次总额度，没有依据时不调用选文模型。私人书籍、群聊笔记或无法核验公开来源的记录不会进入这组旧笔记。笔记及原阅读有过修订，即使后来恢复相同正文，也不作为这组连续阅读依据；这些来源、修订与活动依据 ID 随现有加密备份保存。

0.3.33 的备份数据结构为版本 5，新增聊天约定，仍兼容导入结构版本 1–4。版本 4 起包含对话来源屏蔽记录。恢复时合并本实例已有的屏蔽记录，较早备份不会解除这些来源在模型近期历史和对话检索中的屏蔽。恢复仍会替换书架正文，不能据此认为所有后续修订都会保留。版本 5 备份请使用 0.3.33 或兼容的更新版本恢复。

0.3.22 起，助手回复直接关联当次参考的历史助手消息，持续主动聊天也能保留撤回依赖而不反复复制全部旧来源。保留这种引用传播行为需要使用 0.3.22 或兼容的更新版本恢复。

## 读书与自主表达配置

书房支持 UTF-8 TXT（单个不超过 1 MiB，较大书籍分章导入）和单个 HTTPS 网页正文。创建人可在绑定 QQ 的私聊中发送 TXT，或明确提供本条消息中的网址让她收录；也可在后台上传或导入。QQ TXT 自动收书和后台导入本身不调用模型，通过聊天导入网址会使用正常的模型工具调用与回复额度。收录不会将整本正文写入聊天记录。群聊不可访问创建人的私人书房。

启用自主读书后，默认每天最多 2 次、每次约 3000 字符，在 `Asia/Shanghai` 时区的 09:00–23:00 随机安排，可在后台调整。每次笔记输出最多 700 tokens，与聊天共用模型额度。服务停止时不会阅读；在线导入只收录当前页，不追抓整站或其他章节。创建人日常可通过聊天查书架、阅读位置、笔记，或指定一本书读一小段。聊天阅读无需开启自主读书，与手动、定时阅读共用每日读书额度和单次长度，不受定时活跃时段限制。

连续阅读会从同一本书的真实阅读记录中，取最多三条有效旧笔记作为背景，每条最多 1000 字符，截断会明确标记；不会额外调用模型整理背景。修改过、删除的笔记和其他书籍不参与，旧笔记也不能当作原文事实或未读章节。相关笔记或书籍在生成期间变化时，不保存该结果或推进进度，尝试仍计次。旧笔记、来源记录和阅读进度随现有加密备份保存，重启后仍可继续；不新增会话历史依赖。

自主表达与阅读分别设置。QQ 支持空间动态、签名和头像，需要协议端提供相应能力；Windows 上的小黑盒发帖、评论与回复需要已配置并登录的[专用 MuMu 设备](android.md)，评论和回复另需 Google Android CLI 与 SDK Platform Tools。各平台与动作可分别开关，评论和回复默认关闭。发帖、评论与回复共用每天 80 次的默认总额度，可自定义 0–100，同时受各平台上限、时段和间隔约束；失败和结果未确认也计次。模型可以选择安静，80 次并非必须完成的任务。Linux 核心服务目前没有小黑盒客户端发布适配。绘图 API 只保留配置入口，尚不调用；保留密钥为空不影响现有聊天、阅读和内置表情。

## DSH 只读插件接入

此功能可选。核心服务仍使用 Node.js 22.16 或以上；独立插件宿主需要 Node.js 24。目前固定支持 DSH `0.2.1-rc.2` 与 `dsh-bili-humanism` `1.7.0`，另可按下文分别配置 `dsh-speak-up` `0.2.2` 用于主动搭话、`dsh-feiyu-mood` `0.4.3` 用于对话心情评估；不扫描或自动启用其他插件。可以在 Windows 或 Linux 配置对应系统的 Node.js 路径。

在项目和个人 DSH 配置之外建立专用宿主目录。下载作者 [1.7.0 发布页](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/releases/tag/v1.7.0) 的 `dsh-bili-humanism-1.7.0.tgz`，在专用目录使用 Node.js 24 附带的 npm 安装：

```bash
npm init -y
npm install --ignore-scripts --save-exact @deepseek-ai/dsh@0.2.1-rc.2 /absolute/path/dsh-bili-humanism-1.7.0.tgz
```

将示例中的包文件路径换为实际下载地址。在 Memoria 的数据目录创建 `dsh-runtime.json`（默认数据目录为项目中的 `data/`）：

```json
{
  "enabled": true,
  "nodePath": "D:/tools/node24/node.exe",
  "hostDirectory": "D:/tools/memoria-dsh-host"
}
```

Linux 可分别填写 `/opt/node24/bin/node` 和 `/var/lib/persona-agent/dsh-host` 等实际绝对路径。Memoria 服务用户须有执行 Node 和写入专用宿主目录的权限。使用仓库 systemd 模板时，宿主放在可写的 `StateDirectory` 内；其他位置还须加入该服务的 `ReadWritePaths`。此文件仅由部署者在本机设置，不接受聊天或插件修改路径。无需在 DSH profile 中填写模型密钥或复制个人配置。

使用 WSL 时，将 Linux 宿主及其 `node_modules` 安装在 Linux 文件系统，例如 `~/memoria-dsh-host`。从 `/mnt/c` 或 `/mnt/d` 加载大量依赖可能导致启动超时；不要复用 Windows 的宿主依赖目录。

在后台“人格与设置 → DSH 插件运行层”点击检测。此按钮启动独立子进程，核对真实插件注册及只读开关，不调用模型或平台；结束后关闭宿主并清理临时 profile。关闭方法是将 `enabled` 改为 `false` 或移除配置文件，无需改变聊天与书架设置。

启用后，可以在聊天中提供完整的 `https://www.bilibili.com/video/BV…/` 链接让她读取视频文字，也可使用“网页阅读”或把链接加入固定网址阅读安排。支持 `?p=2` 等 1–100 的分 P 参数，分享追踪参数会移除；不解析短链。不下载视频、不抽帧或执行 ASR；平台未返回字幕时不会保存为已读，不能凭标题或搜索摘要补写内容。

部分字幕需要登录。在“人格与设置 → DSH 插件运行层”点击“登录 B站专用账号”，由你在项目独立浏览器里手动登录，然后回后台点击“完成登录，保存状态”。Windows 使用已安装的 Google Chrome 独立资料目录，不读取日常浏览器登录；Linux 需要图形会话和完整 Chromium（`npx playwright install chromium`）。无图形会话的 Linux 服务当前无法完成本机交互登录，可以先匿名使用。这里保存的是栖忆的执行账号，不会把它绑定成创建人。

也可以导入当前 Chrome 中已有的 B站登录，无需在自动化窗口重新登录：

1. 在已登录 B站的那个 Chrome 资料中打开 `chrome://extensions`，启用开发者模式，选择“加载已解压的扩展程序”，加载本项目的 `extensions/bili-login-bridge` 目录。
2. 用同一个 Chrome 打开 `http://127.0.0.1:3210` 并登录创建人后台。在“人格与设置 → DSH 插件运行层”点击“从当前 Chrome 导入 B站登录”。看到已保存提示后即可移除扩展。

登录桥只在点击时读取 `www.bilibili.com` 下的 `SESSDATA` 和 `DedeUserID`，经已登录的本机后台保存；不读取浏览历史或其他网站，不执行自动同步，导入过程不向模型或其他服务传送登录状态。它只接受来自上述本机地址的请求，其他端口、远程地址和内置浏览器不能使用此导入按钮。保存在本机的状态会保留到重新登录或更换；退出 Chrome 的 B站登录后，本机副本不一定立即失效，请在 B站账号管理中撤销不再使用的会话。这里不读取 Google 登录、不复制或解密 Chrome 资料目录。[Chrome 扩展加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-an-unpacked-extension)

专用浏览器资料留在数据目录的 `bili-browser/`；读取所需的登录状态保存到 `bili-credentials.json`，不进入 GitHub、结构化备份、模型消息或字幕域请求。只向 B站固定只读 API 携带 SESSDATA，不开放发帖、评论、点赞或其他账号写入。后台“已保存”仅表示本机存在配置，不证明平台认证仍有效；失效后可重新登录。登录不会自动解除已有风险暂停。

新读取由栖忆统一登记尝试：默认每天 6 次，所有场合共用，后台可调整为 0–50，按 UTC 日期计数。失败、无字幕和进程启动失败也计次；检测与翻阅已有书架不计次，重启或换 DSH 会话不清零。固定网址计划还遵守其原有间隔和每日次数。单次采集受插件 90 秒、最多 12 个网络请求约束；字幕文字上限 600000 UTF-8 字节，超限明确失败，不截断后声称完整获取。聊天后续理解与回复继续使用栖忆已配置的模型和每日模型额度，字幕取稿本身不调用模型，也不占公开发布的 80 次额度。

取得的文字带时间戳、来源与覆盖说明，按最多 50 段、每段不超过 30000 字原子存入书架；任一分段失败都不留下半份成功记录。搜索或翻阅任意有效分段时，可取得同次资料的分段索引，逐段继续阅读。保存全文表示留存本次取得的全部文字，不表示观看画面、听过声音或覆盖完整视频。书架分段及其索引、来源随栖忆加密备份迁移。

要让她自行发现内容，在“自主浏览”来源中勾选 B站并启用日程。小黑盒与 B站可单独或同时选择，共用每天的随机活动机会；旧配置保持只选小黑盒。每次 B站活动先读取最多三条热门候选，再由栖忆在本机按配置兴趣、人格关键词、未读记录与失败冷却选择一条；只把所选网址交回 DSH，不将私聊或人物记忆发送给平台。发现和取稿共用一次 DSH 每日尝试，原生宿主全程最多 12 次网络请求；没有未读候选便保持安静，失败视频冷却 24 小时，不在同次活动中换片重试。

成功取得文字后，先把全部分段存入栖忆书架，再通过 DSH 原生模型接口写笔记。此笔记任务只取得当次公开文字的前 8000 字符、来源与覆盖说明，不携带私人旧笔记、聊天、平台凭据或模型密钥。栖忆在父进程加入当前人格资料，使用后台配置的模型完成一次纯文本请求，最多输出 650 tokens；与聊天共用每日 200 次模型请求上限，失败与取消也计入尝试，不重试或改用另一条模型链。插件不能选择模型服务地址、覆盖密钥或调用写入工具。

笔记存回栖忆书架，不依赖 DSH 会话。笔记失败或额度用完时保留已保存的阅读正文；笔记任务不重复取稿，也不再占用 DSH 阅读尝试或公开表达的 80 次额度。分段正文全部保存不表示模型当次读过所有文字；笔记会保留资料覆盖说明。创建人私聊中说“现在去B站逛一下”也可触发一次，仍须已启用 B站来源并受相同额度限制；指定小黑盒时只浏览小黑盒。普通问候、询问过去是否读过或引用里的请求不会触发新的 B站活动。此阶段只浏览、取文字和记笔记，不执行 B站公开表达。

采集缓存和平台风险暂停持久保存在数据目录的 `dsh-cache/humanism/`，跨子进程共用；不要通过删除缓存或换会话绕过平台暂停。缓存属于执行状态，不包含在结构化记忆备份中；机器路径配置也不会随备份迁移，新实例须核对目标平台访问情况后再配置。当前不开放评论、语音或其他未经接入的 DSH 插件；可选主动搭话的安装见下文。

DSH 通过栖忆提供的搜索、分页正文和来源工具读取当前场合获准使用的记忆。场合与发言者由栖忆确定，工具参数不能指定或扩大权限。每次读取查询当前书架；换会话或重启宿主不会清空已存记忆。长期记忆、来源、修订和删除记录继续进入栖忆加密备份，临时插件缓存不属于备份内容。单次模型上下文仍有限，保存的信息需按问题检索和分段读取，不保证一次调用回想所有经历。

聊天和 DSH 搜索每页最多提供 6 条匹配及当前可见的命中总数，可以继续翻查后续页，再按记忆 ID 读取正文或核对原话。较早记录不再因排在首屏之外而无法取得索引；需要时可以在聊天中要求“继续查同一主题的更早记录”。搜索结果的位置按条目计数，正文和原话的位置按字符计数，二者分别翻页。搜索只统计获准范围内未删除的记录；修改、删除后结果立即反映当前书架，排序变化时需从第一页重新核对。每轮聊天仍最多调用 5 次工具，不会为了列完书架自动增加整轮模型预算，也不表示一次对话能读完全部长期记忆。

书架没有收录的细节可通过 `search_conversations` 查找历史对话，再用 `read_conversation` 分段核对，每页分别最多 6 轮和 4000 字符。检索不依赖最近 16 条消息仍在模型上下文内，且不额外调用模型整理档案。用户原话、助手旧回复和各自时间分别标明；助手旧话可能有误，不能当成用户事实。旧版记录只要保留明确、有效的消息与回复关联，也能提供已完成轮次；缺少关联或未完成的记录不猜测匹配。创建人私聊、其他私聊和群聊沿用各自可见范围，模型不能通过参数指定另一场合。

修订或忘记对话来源记忆后，关联原轮次不再进入档案检索和模型近期历史；引用了被屏蔽来源的助手回复也会隐藏，独立用户原话仍保留。旧版来源缺少消息 ID 时，同一场合、同一发言者的相同原话会一并屏蔽。恢复备份后若删除或修订证据仍在、对应来源已缺失，该场合无法确认来源的旧记录会暂不提供；有完整来源关联的新记录仍可使用。依赖按实际读取和近期历史记录，不保证识别未关联的重复事实。原始聊天和事件仍保存在本机；有效书架条目的来源核对保留，便于比较原话和当前修订。

启用上述 DSH 运行层后，聊天还可以按需调用原生记忆子代理，例如“让记忆子代理核对一下最早的约定和原话”。它会建立真实的 agent/session 回合，开放书架搜索、记忆正文、记忆来源、对话搜索和对话正文五种只读工具。栖忆固定当前身份与可见范围，直接取得工具结果并保存模型历史；子代理不能指定其他账号或范围，群聊不会取得创建人的私聊。简单查询仍可直接使用原有记忆工具。

每轮聊天最多尝试一次子代理任务，内部最多 4 次模型请求、5 次记忆工具；第 4 次请求不再提供工具。内部模型请求与外层聊天共用每日 200 次总额度，公开发布和 B站读取分别计数。父进程累计模型上下文最多 80000 字符，超过便终止，不截断后声称已经查完；失败或取消不自动重试。最终回答需与栖忆实际收到的完整模型回复一致，截断回复不会当作成功结果。

记忆子代理或主动拟聊因额度用完、回复格式不符、请求未完成或所用资料变化而停止时，会保留能核实的原因；聊天仍会说明失败不等于没有相关记忆。未知故障显示通用提示，不自动重试。阅读笔记与心情任务也会区分已核实的额度、回复格式和请求失败。

普通记忆子代理会重新核对实际读取或搜索返回的条目、原话、对话及分段索引；修改正文节选之外的内容、删除条目或改变可见范围，也会使本次结果失效。核对覆盖子代理运行、结果回传和后续主聊天回复保存之前；来源变化后停止基于旧结果回答，已经发生的模型调用仍计次。此检查针对子代理使用的资料，不表示普通聊天所有初始资料都已获得相同的持续核对，也不能撤回已经发出的消息。

原生回合结束后释放 agent 并清理临时会话，长期记忆仍在栖忆数据库；新任务重新按范围检索。正常收到 SIGINT/SIGTERM 时会取消并等待当前 DSH 任务清理，强行结束进程无法保证清理完成。此记忆入口不访问平台或写入记忆，也不自动加载其他 DSH 插件、定时器、朗读或第二套 QQ 消息桥。

主动私聊也可复用原生回合。栖忆从过滤后的创建人场合自行核对消息和有限背景，提供统一人格、抽象心情和记录时间；插件不能指定其他场合或收件人。最终只产生一段拟聊文本或选择安静，栖忆再次核对来源、QQ 登录账号和发送上限后决定发送。读取过的记忆正文、原话或依赖在生成后、发送前变化时取消；使用来源的完整记录核对，正文节选之外的修订也会使结果失效。默认使用原生主动拟聊，也可选用下述原版插件触发同一个临时 agent。

### 可选原版主动搭话

此项只切换主动拟聊的触发方式。先完成上述独立宿主安装，再将原版 [`dsh-speak-up`](https://github.com/Yuuyuko-uu/dsh-speak-up) `0.2.2` 安装到同一个宿主目录，使用该目录的 Node.js 24 和 npm。无需放入 Memoria 源码目录或个人 DSH profile。

安装来源固定为提交 `7a9dee46d4f89946738a598990f3ec1c26d1635f`。在独立宿主目录下载并检查归档；不要替换为 `main` 分支地址或不带版本的 npm 包名。

## 心情与节奏

在“人格与设置 → 心情与节奏”开启间歇评估，需要已配置 DSH 与模型 API。默认关闭；开启后默认每 180 分钟最多一次、每天最多 4 次，可设置 60–1440 分钟和每天 0–12 次，按 UTC 日期计数。每天设为 0 会停止新评估。关闭浏览器后，运行中的栖忆服务仍会按间隔检查；没有新资料便保持安静。

每次只选最近 24 小时内的一段已完成对话，或一份已保存的小黑盒、B站公开阅读资料。不同私聊或群聊不会合并进同一次评估；引用先在栖忆核对，再将最多 3000 字符的当次文本和最多 1500 字符的回复交给独立 DSH 任务。历史图片不会重新传送。模型使用相同人格和栖忆配置的服务，每次最多一次请求、300 输出 tokens，与聊天共用每日 200 次总上限，不重复占用 DSH 视频读取或公开表达额度。

模型只提出心境值的 -10 至 10 变化、固定情绪和置信度；把握不足、格式无效、取消或原资料改变时不应用。评估失败和取消也计次，同一资料不自动重试，重启或修改设置不清空已用次数。后台“评估一次心情”可提前自动间隔，仍须已开启、有新资料并遵守上限。

心情评估和主动私聊使用与普通聊天一致的来源屏蔽，关联记忆被修订或忘记后，不再以相应旧对话和旧助手回复生成新结果；生成期间资料变化会取消结果。主动私聊仍按真实最近发言计算安静期，来源屏蔽不会缩短等待时间。原始记录仍可在创建人后台查看。

对话、自主表达和主动私聊共用栖忆保存的数值与固定标签，不读取另一场合的私人原因、姓名、引用或关系描述。心境只作语气参考，不改变平台开关、表达欲、安静时段或发布额度。它表示角色状态，并不证明真实感受或实际发生的经历。

未评估时初始值为 70、情绪为平静；数值偏离按 3 小时半衰向 70 回稳，六小时后标签回到平静。回稳在本机计算，不调用模型。状态及评估事件随加密备份迁移；恢复后新评估暂停，运行配额和模型凭据不从备份导入。

默认使用栖忆原生心情评估，设计灵感参考[鱼的心情](https://github.com/Yuuyuko-uu/dsh-feiyu-mood)。也可按下文安装原包，使用其真实对话钩子和判定算法；统一心情仍由栖忆保存，不导入个人 DSH 会话、配置或状态文件。

### 可选表情关键词检索

先完成上述独立 DSH 宿主安装，再在该宿主目录安装 [`dsh-meme`](https://github.com/yyh-001/dsh-meme) 固定版本：

```bash
npm install --ignore-scripts --save-exact dsh-meme@0.1.60
```

Windows PowerShell 使用 `npm.cmd`。保留原包、MIT 许可和生成的锁文件。在数据目录现有 `dsh-runtime.json` 中加入 `expressionPlugin`；保留已有的主动搭话、心情等字段，路径使用自己的绝对路径：

```json
{
  "enabled": true,
  "nodePath": "C:/path/to/node24/node.exe",
  "hostDirectory": "C:/path/to/memoria-dsh-host",
  "expressionPlugin": "dsh-meme"
}
```

Linux 使用对应系统的路径和依赖。后台的 DSH 状态会显示“按需关键词检索”；点击检测只核对固定包，不调用模型或发送图片。删除 `expressionPlugin` 字段即可恢复原有目录选择。

启用后，聊天想配表情时先按简短关键词搜索，每轮最多两次、每次最多六张；模型看到候选后再选一张。只有内置图库、创建人上传图库和本次原私聊或原群的收藏参与检索，新收藏下次聊天才可选用。删除的图片不再作为新候选，发送前仍核对原场合和图片是否存在。

接入使用原包的本地关键词匹配函数，不是向量检索或视觉模型，不额外调用识图模型，不创建另一套图库或发送通道。关键词搜索本身不花模型额度；模型决定搜索、选择和回复仍占正常聊天轮次与每日总额度，单轮上限不增加。缺包、版本或文件校验失败时，本次检索返回失败，聊天仍可只用文字，不自动重试或发送任意图片路径。

参考：[Node.js 下载](https://nodejs.org/en/download)、[systemd 执行环境与 StateDirectory](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)。
