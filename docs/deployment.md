# Windows 与 Linux 部署

可选飞书文本通道使用独立的原版 DSH 消息宿主，安装、应用身份核对和后台设置见[飞书接入说明](feishu.md)。主服务与聊天渠道分别配置；默认不启动飞书连接。

Memoria 使用 Node.js 22.16 或更新版本、npm 和 Node 内置 SQLite。Linux 启停脚本需要 Bash 4.4+ 和已挂载的 `/proc`，不依赖 Docker。请安装对应系统与 CPU 架构的 Node.js，再执行 `node --version` 确认版本；不要把 Windows 的 Node 或 `node_modules` 目录复制到 Linux。

小黑盒自主浏览另需 Playwright 的 Chromium headless shell。浏览器系统要求比纯聊天更严格，建议选择官方支持的 Windows 11 / Windows Server 2019 或更新版本，以及 Debian 12/13、Ubuntu 22.04/24.04/26.04；Linux 使用 x86-64 或 arm64。具体支持范围以 [Playwright 系统要求](https://playwright.dev/docs/intro#system-requirements)为准。

程序只监听 `127.0.0.1:3210`。本地管理后台需先设置管理员密码，模型 API、QQ 登录和云盘授权分别配置。部署程序不会自动登录这些外部账号。

后台用于配置与管理；完成 QQ 绑定后，创建人可通过私聊进行日常对话、发 TXT 收书和查询阅读进度。无需每次打开后台。

运行不需要 Codex 或其他开发工具在线。服务直接调用已配置的模型 API，自己执行调度并保存数据；关闭管理网页不会停止服务。Windows 后台启动和 Linux systemd 的具体方式见下文。

## 聊天中的网页阅读

在当前消息中直接分享完整 HTTP(S) 网页地址，可由模型按聊天需要读取；单独网址、Markdown 链接，以及用引号或反引号包住的纯网址都可作为目标。网址须来自本次直接正文，历史消息、QQ 引用上下文和图片中的网址不提供阅读要求。

程序会在读取前排除引用或代码里的完整命令、明确否定、转述、历史回顾和条件或未来打算。例如“不要打开 A”不会读取 A；“A 不读，帮我看看 B”只允许 B；明确说“今天只想聊天”会阻止本条所有链接的临时阅读。同一网址同时要求阅读和禁止阅读时不执行，请另发一条明确的当前请求。合并的 QQ 消息也保留“不要打开这个链接”与后续网址的关联，不会把后续单独网址当成新的允许。

混合转述、条件和多个目标的复杂句式可能被保守拒绝，单独发送完整网址并说明现在要读即可。读取成功后仍按当前聊天场合保存网页及来源；失败不会假称已读。这里的检查只约束聊天临时阅读，后台“网页阅读”、固定网址计划和自主浏览沿用各自的配置与额度。

## 私聊中的书架线索

配置模型后，创建人与其他获准对象的私聊会保留原有关键词检索，并从当前私聊书架补充少量“人物”“兴趣”标题线索：每类最多 2 条，共最多 4 条，按最近修改排序，跳过本轮相关检索中已出现的条目。只提供标题和基本索引，正文与原话仍由模型按需翻阅。索引在本机生成；后续检索和模型请求沿用原有次数限制。

例如“今天想轻松聊聊，别让我选题了”没有具体兴趣关键词时，这些线索可帮助她自行核对一个旧话题。普通问候仍可以简单回应，不要求每次翻阅或提起旧事；少量索引也不能代表完整书架或全部偏好。来源发言者与内容主体需要区分，朋友的兴趣、转述和引用不会因此得到新的身份认证。手工条目可以作为线索，缺少对话来源时不能声称核对过原话。

各私聊仅使用自己的范围，不合并公开书架、其他人的私聊或群聊。更正、删除索引条目或改变其来源后，尚未完成且依赖旧版本的回复会停止；已经发出的内容无法保证撤回。离线演示仍只显示关键词检索结果。

## 历史主动私聊

创建人可以在已验证私聊或登录后的后台聊天中询问“你上周主动对我说过什么”，按日期、关键词搜索已确认发送的主动私聊，再分段核对原文。普通聊天和 DSH 记忆子代理共用这些本机档案，查询沿用现有工具步数与模型额度，不依赖近期上下文一直保留这段话，也无需先开启主动私聊开关。

这些记录明确标为她当时主动发送的原话，不包含用户回应，不能证明用户偏好或提供新的操作授权。新记录可按核验后的 QQ、飞书来源筛选；旧记录能核对发送结果但缺少平台证明时，只参与不限定平台的检索。未确认发送、缺少可靠关联或来源已更正、忘记的内容不会进入这项检索；查不到不能据此断言她从未说过。

主动消息和对应发送记录随现有加密备份保存。所引用的资料在生成或送达归档前变化时，会停止继续使用这项历史；已经发出的消息无法保证撤回。恢复后的身份绑定和主动开关仍按原有规则重新核对。

## 临时免打扰

创建人可在已验证私聊或登录后的后台聊天中说“先别主动找我两小时”“暂停主动私聊30分钟”。明确整数时长支持 1–1440 分钟或 1–24 小时，从成功应用时开始计时；再次明确设置期限会替换原期限，从本次应用时重新计时。可以询问“主动聊天现在是什么设置”，后台主动私聊摘要也显示当前截止时间。

期限只限制主动私聊及约定跟进，QQ 与飞书共用；普通聊天、公开表达和自主阅读沿用各自设置。免打扰期间不发起新的主动拟聊或发送，不清空已用额度、未回应记录或修改约定期限。到期后继续遵守原有开关、时段、空闲、冷却和预算，过期约定不补发，也不保证到点开口。已经发起的模型请求仍计次，已经在途的发送无法保证撤回。

“结束主动私聊免打扰”只清除期限，原开关保持不变；“恢复主动私聊”同时清除期限并开启主动私聊。未提供时长的暂停仍持续到明确恢复。“今天别”“明天再开启”、延长多久等不明确要求会先澄清，引用、代码、转述或图片不提供操作授权。保存失败时不取消在途主动任务，应查询当前状态再用新消息确认。

截止时间保存在本机配置中，重启后仍有效。现有记忆备份不迁移这项运行配置；在本机恢复备份仍保留本机期限并关闭主动私聊，换机后默认关闭，均不会因期限到达自动开启。

## 模型额度与私聊预留

在“人格与设置 → 对话模型”调整“创建人私聊预留请求数”（`ownerChatReserve`），默认 20，接受 0–200 的整数；0 关闭预留，200 停止普通任务的模型调用。每日按 UTC 日期计算的全局 200 次模型请求总额不变。设为 20 时，普通任务共用前 180 次，最后 20 次仅供创建人当前发起的私聊及该轮 DSH 记忆检索；创建人私聊也计入同一总额，不另开一份额度。

群聊（包括创建人在群里发言）、其他人的私聊、她主动发起的聊天与约定跟进，以及阅读、笔记、心情、记忆整理等后台任务和“测试模型连接”，均使用普通共享额度，到预留线时不再调用模型。

一次聊天可能使用多次模型请求，已经发出的失败调用仍计次。修改预留数不会清空当天已用量；降低预留也不会退回已用次数。预留只控制模型请求分配，QQ、飞书等渠道聊天限额、并发限制和 DSH 忙碌状态仍可能阻止处理，不保证可完成的聊天轮数。

## QQ 对话额度

在“人格与设置 → QQ 接入”调整“每日智能对话尝试上限”，默认 200，范围 0–1000。QQ 私聊、群聊与主动私聊的模型拟聊共用此额度，按 UTC 日期保存；处理前预留一次，处理或发送失败、模型拟聊选择安静也计次，不退回。本机 Mate 节奏判断未调用模型时不计 QQ 智能尝试。主动私聊仍受自身发送和判断上限约束。

设为 0 或额度用尽后暂停新的智能处理，不发送限额提醒，也不积压消息等待补发。身份绑定和 TXT 收书命令仍可使用；未获准的消息和重复事件不扣次。后台显示今日已用与剩余，聊天中也可查询。

同一实例重启、修改配置或恢复备份不会清零本机当天已用次数；这份运行计数不随备份迁移到新实例。本机后台聊天不占 QQ 额度。每日 200 次模型请求和全平台 80 次公开发布仍分别计数；一次聊天可能使用多次模型请求，因此调高 QQ 上限不会提高模型总额度。

### 普通群消息关注

在“人格与设置 → QQ 接入”调整“普通群消息关注概率（%）”和“同群自主关注间隔（秒）”。概率默认 0，范围 0–100，0 保持仅处理 @ 的现有方式；间隔默认 300 秒，范围 60–3600。只有白名单群内未 @ 的普通消息会参与概率关注，抽中后由模型判断是否适合回应，也可以保持安静。

抽中即占用该群的关注间隔，模型安静、处理失败或发送失败都不退回；不同群分别限制。@ 消息继续走正常处理，不受这项间隔限制。进入模型的关注判断与私聊、@ 回复和主动私聊共用 QQ 智能对话额度，每次实际模型请求仍计入每日 200 次总额度，不新增发送额度或保证回复。

未抽中的消息不进入智能处理，也不下载其中的图片；开启此功能不代表长期保存全部群聊。处理后的对话、图片理解、阅读和记忆沿用当前群的可见范围，创建人在群里发言也不会带入其私人记忆。

### 连发文字与取消

在“人格与设置 → QQ 接入”调整“连发文字等候（毫秒）”，默认 700，范围 0–1500，0 关闭合并。只合并同一发言者在同一私聊或同一群内连续发来的纯文字；每批最多 3 条、合计 8000 字符，自第一条起最多等候 1800 毫秒。不同群友、图片、文件或绑定命令会结束当前合并；群内未 @ 的消息只有通过上述关注判断才进入智能处理。同一聊天的智能回复按批次顺序处理，绑定与收书确认仍可独立返回。

每条原始消息分别去重；一批只预留一次 QQ 聊天尝试，实际模型请求仍逐次计入模型总额度。合并正文以换行分隔，原消息 ID、接收时间和正文位置保存在本机消息与经历中，随加密备份保存。模型仅获得合并条数及说明，核对原话时会标明多条合并。更正或忘记相关来源时，原有整轮对话屏蔽规则仍适用。

关闭 QQ、更改 QQ、模型或人格配置，以及修改账号绑定，会取消待处理批次，并阻止在途聊天继续生成和发送回复。创建人通过后台或其他渠道发起新的私聊、在后台手动更正记忆，也会取消尚未完成的旧 QQ 回复；QQ 自身仍按同一聊天的批次顺序处理。已经启动的读书、书籍导入等独立任务可能仍保存结果，取消聊天不回滚已完成的资料操作。已经发起的模型请求仍计费、计次，已经在途的发送无法保证撤回，不自动重发。待处理队列仅保存在内存，进程退出或异常中断后不恢复补发；需要时请重新发送。

### 回复节奏与部分发送

在“人格与设置 → QQ 接入”可开启“分段发送聊天回复”，并调整“最长回复停顿（毫秒）”。默认关闭分段、停顿为 0，保持原有单条立即发送；旧配置也使用这两个默认值。停顿范围为 0–5000 毫秒：0 不等待，非 0 时按文字长短与少许随机变化决定发送前及段间的停顿，每次不超过所填上限，并非固定等待时长。

分段只使用模型回复中已有的自然空行，最多发送 3 段；含代码围栏时保持整条，文字合计仍最多 5000 字符。不会为分段或停顿额外调用模型，整次智能回复沿用一次 QQ 聊天尝试，表情仅随最后一段发送。此设置用于 QQ 私聊、群内 @ 和获准的普通群消息智能回复；绑定、TXT 收书、错误确认和主动私聊不受影响。

每段发送前都会重新核对当前身份、配置和取消状态。关闭或修改配置、解绑、收到上述新的创建人聊天或更正记忆时，尚未发出的后段会停止；已发出的前段无法撤回。任一段失败或结果未确认后，不继续发送余段，也不自动重试。只有协议端确认发出的文字会逐段计入同一条助手回复；没有任何确认时不保存助手回复，未确认发出的尾段不会进入回复历史、检索或备份。协议端确认表示接口已接受，不能据此保证客户端实际可见。

没有到期约定时，主动私聊开启且 DSH 可用便优先从最近七天内仍可见、尚未判断过的创建人最新私聊延续近况，再考虑实际阅读。两者都没有候选、且自上次创建人私聊后没有主动发送尝试时，也可核对来源仍有效的书架旧主题；发起过发送便暂停这条补充路径，直到创建人再次私聊，发送失败或未确认也计入。无需安装 Mate；启用可选 Mate 内核后，沿用其节奏判断，在阅读之前考虑旧主题，内核异常不改走补充路径。未启用 DSH 时仍可考虑实际阅读。每个原生回合最多 4 次模型请求、5 次只读工具；阅读判断最多一次模型请求，随机话题与约定跟进共用每天最多 6 次判断。同一机会只选择一种话题，安静、失败或取消后不立即转为另一种。每次判断占一次原渠道智能对话尝试，每次模型请求分别占全局额度。默认主动私聊仍关闭；原有每天最多 1 次发送、安静期、活跃时段与机会间隔继续生效。

随机话题中的同一条最新私聊、同一网页地址、同一已读书籍片段或旧主题条目的同一版本，在判断开始前记入持久去重；安静、失败和取消也不自动重试。同网址再次读取产生新条目，仍按同一来源处理。判断事件随备份保存，本机还保留独立的执行去重记录；恢复较旧备份不会重试同一来源，也不会清空本机当天已用的主动判断或发送计数。恢复仍会暂停主动私聊并清除账号绑定。新机器恢复判断前的旧备份时，无法得知后来发生的判断。

### 私聊的空闲记忆整理

在“人格与设置”调整空闲记忆整理，默认开启、间隔 180 分钟、每天最多 4 次；间隔可设为 60–1440 分钟，每日上限为 0–12 次，设为 0 则不调用模型。只有所选私聊最近 10 分钟没有新消息且其他任务空闲时才会尝试。每次从一个私聊中选取最多 12 条、合计不超过 24000 字符的有效原话，模型最多选择两条；每个来源只保存一条完整原话和索引标题。人物、经历或兴趣条目进入原私聊的书架范围，群聊不参与此项整理。

首次开启以当前聊天位置为边界，只处理后来收到的原话；重启沿用边界，关闭后再开启会重新建立边界。收到新聊天、修改相关配置或来源发生变化时，在途结果停止保存；已经发起的模型请求仍计入额度。后台分别显示今日尝试次数和上次实际新增条数，不将失败或安静算作新增记忆。每批尝试前保存去重记录，失败、取消和安静均不自动重试。本实例恢复旧备份不清空本机当天计数及尝试去重；新机器无法知道旧备份之后的尝试。恢复后整理暂停，重新开启只处理后来的新原话。

保存的是原始用户消息，保留引用和说话主体，不由模型重写成已确认事实；助手是否成功回复不影响原话本身的有效性。图片、记忆管理指令、已屏蔽来源、已有同来源记忆和同范围内已保存的完全相同自动整理正文会跳过。此去重不能识别所有换句话说的重复内容。每次至多请求一次模型，与现有每日 200 次模型额度共用，不产生平台消息或公开发布。

### 更正后的记忆与主动话题

明确纠正旧记忆时，聊天会先核对并修订原条目；找不到目标或修订失败，不会退回新增一份记忆。否定、引用和代码中的旧记忆操作不能用来另存旧内容。这是对明确操作用语的检查，不能识别所有改写后的重复事实。

在创建人当前私聊中明确更正记忆后，栖忆会把这次更正原话与当前条目的完整版本关联。启用主动私聊和 DSH、且原渠道仍有效时，这条当前记忆可以再次成为旧话题候选；按新的更正请求核对渠道，保留原条目的旧出处，不把话题改投另一平台。更正并不保证她一定主动提起，也不取消原有机会间隔、未回应退避、判断或发送限额。约定类条目仍按跟进规则处理，更正后不会自动恢复旧约定。

主动拟聊按需检索时，可以读取仍有效的当前私聊记忆正文；后台手动编辑或旧出处被屏蔽，不会仅因此使整次检索失败。旧原话会明确标作历史资料，不能覆盖当前正文或作为新的操作授权。后台编辑没有新的私聊更正来源时，不会因此获得主动话题的发送渠道。

后续再次编辑、删除，或更正原话、账号及渠道变得不可用时，原有候选会失效；生成和发送前会重新核对。更正请求被屏蔽后，关联主动回复也会退出后续可用历史，已发送的消息无法保证撤回。旧版审计无法可靠追溯绑定到当前版本，不自动补证明；恢复备份保留正文、修订及审计，但不继承这项主动来源关联，需要新的有效聊天更正重新建立。恢复后的账号绑定和主动开关仍按原规则重新确认。

### 可选 Mate 陪伴节奏内核

此项默认关闭，使用原版 [`dsh-mate-companion` 1.5.4 数值内核](https://github.com/m-rui001/dsh-mate-companion/tree/a6d715c1bfa6dcd81eb0dadcb3964e0d459c1c5a/packages/mate/src)。栖忆只在现有随机聊天机会中调用本机算法，参考新交流、好奇、疲劳与未回应后的退避；不启动原版完整 bundle、另一套定时器、模型或文本记忆库。人格、心境与书架仍由栖忆统一管理，数值节奏不代表真实主观感受。

准备目标系统的 Node.js 24、系统 `tar` 命令和网络连接，用运行 Memoria 的同一系统账号，在项目目录执行以下命令。目标须为现有真实父目录下尚不存在的绝对路径，放在程序源码、个人 DSH 配置与任何 `node_modules` 目录之外：

Windows PowerShell：

```powershell
& "C:\path\to\node24\node.exe" .\scripts\install-mate.js --directory "C:\path\to\memoria-mate"
```

Linux：

```bash
/path/to/node24/bin/node ./scripts/install-mate.js --directory /path/to/memoria-mate
```

安装器下载并核验固定原包、完整保留原版源码与 MIT 许可证，不修改个人 DSH 或栖忆设置，也不需要执行原包的构建或安装其完整 bundle。Windows 与 Linux 使用各自的本机 Node.js 路径。成功后，将输出中的 `configuration` 对象单独保存为栖忆数据目录下的 `mate-runtime.json`（默认 `data/mate-runtime.json`），使用 UTF-8 无 BOM；不要保存整个外层输出对象。示例：

```json
{
  "enabled": false,
  "nodePath": "C:/path/to/node24/node.exe",
  "packageDirectory": "C:/path/to/memoria-mate/package"
}
```

Linux 使用安装器输出的绝对路径，systemd 服务账号须能读取该环境。核对配置后，按需将 `enabled` 改为 `true`；关闭或移除此文件可恢复原有随机话题流程。后台“主动私聊”显示内核是否启用、就绪或正在运行。安装和启用内核不会开启主动私聊；旧主题拟聊还需已有的 DSH 运行层，实际发送仍需有效的原渠道创建人绑定、连接、模型及既有额度。

新聊天仍优先。没有新的可用私聊线索时，可从书架中有原话来源的创建人旧兴趣，或真实公开阅读及有效笔记中选择一个主题，重新核对正文、来源与时间后决定是否开口。不使用他人的私聊或群聊、来源不明条目；旧约定不当作新任务，也不因为收到通知就声称新看过内容。生成期间修改、忘记或屏蔽相关来源，会取消尚未发送的结果。

无人回应时减少随机搭话，新的有效私聊后重新评估；好奇、疲劳和开口倾向只提供节奏依据，模型仍可选择安静。到期约定仍优先，不受这项随机话题退避限制，但继续受原有开关、聊天欲为 0、时段、安静期和预算约束。内核计算本身不调用模型；拟聊仍共用每天最多 6 次判断、默认最多 1 次发送，以及原渠道智能对话和每日 200 次模型请求，不增加额度。

若数值状态损坏或未处理历史积压过多，可在后台点击“重置陪伴节奏”；正在主动判断时须等待结束。重置只恢复内核数值状态并从当前聊天位置重新开始，不删除记忆、不清空已用额度、发送去重或未回应记录，不恢复旧消息发送，也不会开启开关。0.3.35 的数值节奏随结构版本 5 加密备份保存；恢复后主动私聊仍暂停，并从恢复时的聊天位置开始，不回放旧联系人或旧发送。内核安装包与本机运行配置路径不包含在加密数据备份中。

### 在聊天中约定跟进

只在已验证创建人身份的私人对话中接受当前明确的纯文字请求；群聊、其他人的请求、引用、转述和图片中文字不能安排跟进。先在 QQ 或飞书原私聊验证创建人绑定并启用该渠道；跟进只发往提出约定的原私聊，原渠道不可用时不改投另一平台。日常入口仍是聊天，后台“主动私聊”仅展示约定状态与时间，不新增操作按钮。

例如分别发送：

- “明晚20:00问问我考试情况”——使用“主动聊天时区”，也可以在消息中明确时区；时间或目标不清楚时先询问。
- “列出我的约定”——核对标题、时间和状态。
- “暂停考试提醒”——保留约定与原时间，停止后续跟进；之后可明确恢复。
- “取消考试提醒”——结束这条约定，之后不能恢复；目标不唯一时先说明是哪一条。
- “恢复考试提醒”——仅恢复仍有效的暂停条目，例如暂时暂停后继续跟进，或恢复备份后重新绑定 QQ；已取消、过期或失效的条目不能恢复。

未来时间范围为一分钟后至 366 天内，最多保留 20 条未结束约定；标题和内容存入统一记忆书架，关联当次创建人原话。每轮聊天创建、暂停、取消、恢复合计最多尝试一次，参数错误和操作失败也计次。修改或忘记关联记忆、屏蔽原话来源以及解绑账号会使原约定失效；需要新的安排时，应在聊天中重新明确提出。

暂停不推迟原到期或截止时间，不清空已用判断次数或发送去重；超过原截止时间后不能恢复。已经发起发送的消息无法保证撤回，发送结果未确认的条目不能重新启用。询问操作含义、要求将来再暂停或取消，以及引用和转述里的要求，不会被当作当前操作；需要定时改变约定状态时应在届时重新明确提出。

主动私聊默认关闭，保存约定不会自动开启。聊天欲为 0、每日发送额度为 0，或账号、模型未就绪时保持安静。到期约定优先于随机话题，但仍受活跃时段、机会间隔、冷却、空闲和预算约束；后台的“下次随机机会”不是约定的发送时间。跟进是机会式关心，不是准点闹钟，也不保证必定发送。

每条约定最多判断 3 次，安静、生成失败或取消也计次，之后结束；到期后 24 小时截止，不补发过期约定。随机主动聊天和约定跟进合计每天最多 6 次判断，共用默认每日最多 1 次发送、原渠道智能对话额度与每日 200 次模型请求总额。DSH 可用时当次拟聊最多 4 次模型请求、5 次只读工具；没有 DSH 时使用一次模型判断。发送失败或结果未确认仍占尝试，未确认标为 `unknown`，不自动重发。

QQ 原渠道会在拟聊前核对协议端在线状态与登录账号。多条约定已经到期时，先按原顺序筛选最多 20 条，在各自原私聊渠道就绪且有智能对话额度的候选中选择一条；较早的 QQ 约定离线或额度用完，不会堵住后来独立且已就绪的飞书约定。跳过的候选仍待跟进，不增加判断次数、修改版本或占用模型、智能对话额度，也不会把其内容改投其他平台。一旦开始判断，无论安静、失败或取消，都不再改选；本次最多判断和尝试发送一条。

全部原渠道不可用时后台显示“原聊天渠道暂不可用”，不改聊其他随机话题。原有机会间隔、活跃时段、安静期和全局额度继续生效，恢复连接后不立即补发。检查期间已核对的候选来源、绑定、设置发生变化，或飞书已就绪连接切换代次时，取消本次机会，避免使用检查前后的混合依据；发送前仍会再次核对，已经执行的模型判断不退回额度。部署时应同时维护 QQ 协议端的独立启动与正常登录，Memoria 的登录启动项只负责核心服务。

调度、身份、书架和额度由栖忆统一保存；可选原版 `dsh-speak-up` 只触发当次拟聊，不启动第二套常驻调度，也不表示完整接入其他 DSH 约定插件。结构版本 5 备份包含聊天约定；恢复会暂停未发送的有效条目并清除绑定，重新验证 QQ 后仍需在聊天中明确恢复。过期、来源失效或发送结果未确认的条目不恢复发送；同一实例保留本机当天已用计数和已发送去重，恢复旧备份不会重新获得额度。

## 代码包与数据

创建人可在私聊中读取或调整主动陪伴的开关、聊天欲、每日上限和机会间隔，例如“先别主动找我”“可以主动找我聊天了”“主动聊天每天最多2次”。这些参数与后台共用，范围不变；变更只在本条明确纯文字授权和当前身份仍有效时保存，不清空已用额度或约定。后台在生成期间修改了设置时，本次聊天更改会停止，避免覆盖。其余时段、空闲期、账号与细分发布参数仍通过原后台管理。

QQ 和飞书主动陪伴沿用同一份设置及日程。升级后先在对应私聊发送一条新消息，以建立核验过的来源渠道；旧的无来源聊天不会被推断成某个平台。飞书新实例恢复备份时没有本机收件执行记录，旧约定保持暂停，需在重新验证后的飞书私聊中重新明确约定。详情见[飞书主动私聊与约定跟进](feishu.md#主动私聊与约定跟进)。

0.3.58 起，创建人在已验证私聊或登录后的后台聊天中，还可查询或明确暂停、恢复“自主浏览”“自主读书”“公开表达”三个总开关，例如“暂停自主浏览，暂停自主读书”。只接受本条直接纯文字中的明确要求，引用、转述和图片文字不作指令。一轮最多处理一次开关调整；失败后先查询当前状态，再用新消息确认，只有成功后才会答复已调整。冲突、条件、限时或将来要求会先澄清。

变更与后台使用同一配置。明确要求同时调整多个开关时，会一起保存，并保留所有其他设置、今日次数、书籍进度、发布去重与跟进；生成期间配置、当前绑定或来源失效时停止本次更改。暂停会取消相应尚未完成的自主任务，已经发起的模型请求仍计次，已经在途的发布无法保证撤回。开启总开关不自动打开单个平台或动作，不立即触发执行，也不补发已消费的机会。公开表达总开关包含自主动态、签名及头像；只要求停止某个平台或单一动作时，需在后台分项调整或明确是否暂停整个公开表达。

将 `src/`、`public/`、`scripts/`、`deploy/`、`docs/`、`package.json`、`package-lock.json`、Windows 的 `*.cmd`、许可文件和文档作为程序包。包中不包含 `data/`、`backups/`、`node_modules/`、`.env`、日志、数据库、`.pab` 备份或真实账号凭据。在目标机器的项目目录执行：

```bash
npm ci --ignore-scripts --no-fund --no-audit
npm run check
```

程序数据默认位于项目的 `data/`。Linux 脚本支持 `PERSONA_DATA_DIR` 指定独立数据目录；启动与停止时必须使用同一目录。`PERSONA_BACKUP_DIR` 指定自动备份目录。systemd 模板把两者分别设置为 `/var/lib/persona-agent` 和 `/var/lib/persona-agent-backups`，避免程序安装目录需要写权限。自动备份目录必须独立于数据目录，不能设成数据目录本身或其子目录。

## 自主浏览器安装

小黑盒自主浏览及聊天、后台中的小黑盒帖子阅读都需要浏览器二进制。QQ 聊天、识图、表情与普通 HTML 阅读可以先行使用；识图还取决于模型是否支持视觉输入。

Windows 在已安装依赖的项目目录执行：

```powershell
npm.cmd run browser:install
```

Linux 桌面或普通用户部署，可一次安装浏览器和系统依赖：

```bash
npx playwright install --with-deps chromium --only-shell
```

这条命令可能为系统软件包申请管理员权限；日常运行浏览器须使用普通用户，并保持 Chromium 沙箱开启。不要用 `--no-sandbox` 或关闭 `chromiumSandbox` 处理启动错误。systemd 专用用户的安装方式见下节。[Playwright 浏览器安装说明](https://playwright.dev/docs/browsers#install-system-dependencies)、[无界面浏览器安装选项](https://playwright.dev/docs/browsers#chromium-headless-shell)。

浏览器默认保存在当前用户的 Playwright 缓存中。自定义缓存时，安装和启动必须使用同一个 `PLAYWRIGHT_BROWSERS_PATH`，且运行用户能读取、执行其中的文件。例如 Linux：

```bash
export PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/memoria-browsers"
npm run browser:install
bash scripts/start.sh
```

Windows 可在同一 PowerShell 窗口设置 `$env:PLAYWRIGHT_BROWSERS_PATH`，再安装并执行 `.\start.cmd`；若改用双击启动，请把相同地址设置为 Windows 用户环境变量。程序不会替你更改系统环境变量。[Playwright 缓存说明](https://playwright.dev/docs/browsers#managing-browser-binaries)。

升级 Playwright 依赖后，按同样的缓存路径重新运行浏览器安装命令。若出现“浏览器无法启动”，先确认运行用户、缓存路径与 Linux 系统依赖；沙箱报错还需检查宿主机、容器或 AppArmor 对非特权用户命名空间的限制。使用普通用户和有效沙箱运行，不通过关闭沙箱继续访问网页。[Playwright 浏览不可信网站的运行建议](https://playwright.dev/docs/docker#crawling-and-scraping)。

## Windows 安装与运行

选择自己有读写权限的安装目录。安装依赖后双击 `start.cmd` 后台启动，`stop.cmd` 停止。访问 `http://127.0.0.1:3210`，使用 `data\setup-key.txt` 中的初始化码设置管理员密码。日志位于 `data\server.log` 与 `data\server.err.log`。

正常启动后会有一个核心 Node 进程和一个隐藏的 PowerShell 监管进程。核心退出时，监管按 5、15、60、300 秒逐步延长等待，之后最多每 300 秒尝试恢复；连续运行至少 60 秒后重置等待。恢复沿用同一份数据、配置和浏览器缓存，不重新安装依赖或清空额度。重复执行启动不会增加另一套核心。

最近一次监管状态保存在 `data\supervisor-status.json`，可区分运行、等待重试和错误；它是记录，是否在线仍需核对实际进程或访问后台。

`stop.cmd` 会记录停止意图，先停止监管，再停止核心；等待恢复期间也可执行，停止后不会自动拉起。需要再次运行时执行 `start.cmd`。监管只负责核心进程退出，不根据模型连接失败、QQ 离线或网页访问失败重启；它不接管 QQ 协议端、平台宿主或模拟器。核心仍存活但无响应、或监管自身被结束时，可手动停止后重新启动。

确认手动启动正常后，可在项目目录为当前 Windows 用户配置登录自启：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\autostart.ps1 -Mode Enable
```

脚本在当前用户的 [Windows 启动文件夹](https://support.microsoft.com/en-US/Windows/Experience/Startup-Boot/configure-startup-applications-in-windows) 创建本项目的快捷方式，登录后隐藏启动同一个后台服务和监管，沿用项目的 `data` 目录。配置自启只影响后续登录；当前服务仍用 `start.cmd`、`stop.cmd` 控制。自启和手动启动同时发生时，启动互斥会阻止重复创建进程。已有的项目自启快捷方式无需重建。此方式仍需要用户登录；注销或关机期间不会运行。

若使用独立浏览器缓存，启用时会保存本次 `PLAYWRIGHT_BROWSERS_PATH` 的值，也可通过 `-BrowserCache` 指定已有的绝对目录；`0` 保留 Playwright 的项目内缓存方式。未指定参数且当前环境变量为空时，会保留已保存的缓存位置。后续改变缓存位置时重新运行启用命令。QQ 协议端、独立平台宿主和模拟器仍按各自的部署方式启动。

查看本项目的自启配置：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\autostart.ps1 -Mode Status
```

该状态表示快捷方式是否已配置，不代表当前服务在线。移除本项目的自启项：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\autostart.ps1 -Mode Disable
```

停用自启保留当前运行的服务、监管和所有数据。`stop.cmd` 只停止本次运行，已启用的自启仍会在下次登录时启动；需要取消这一行为时执行上面的 `Disable` 命令。移动项目目录前，先在原目录停止服务并停用自启，再到新目录重新启用。

## Linux 安装与运行

将程序放在自己有写权限的目录，例如 `~/persona-agent`，安装依赖后运行：

```bash
bash scripts/start.sh
bash scripts/stop.sh
```

以上两条命令分别用于启动和停止，按需要单独执行。请使用 `bash` 调用。

运行日志保存在数据目录的 `server.log` 和 `server.err.log`。

使用独立数据目录时：

```bash
PERSONA_DATA_DIR="$HOME/.local/share/persona-agent" bash scripts/start.sh
PERSONA_DATA_DIR="$HOME/.local/share/persona-agent" bash scripts/stop.sh
```

初始化码位于所选数据目录的 `setup-key.txt`。日志可用 `tail -n 100 data/server.err.log` 查看。若提示 `.start.lock` 已存在，先确认没有另一个启动脚本运行，再用 `rmdir` 删除提示中的空锁目录；不要删除数据目录。无法确认 PID 文件指向谁时，先检查进程，不要直接杀进程。

## Linux systemd 长期运行

以下以 Debian/Ubuntu 为例，程序目录 `/opt/persona-agent`，专用运行用户 `persona-agent`。先把不含私密数据的代码包解压或复制到该目录，确认当前 Node 版本和安装路径：

```bash
command -v node
node --version
```

模板默认使用 `/usr/bin/node`。若实际路径不同，修改 `deploy/persona-agent.service` 中的 `ExecStart`，并同步替换下方命令中的 Node 路径。Node 必须是服务用户可访问的系统安装，不能指向个人家目录中的 nvm 路径，因为模板启用了 `ProtectHome=yes`。同样不要把程序或浏览器缓存安装在个人家目录后直接使用此模板。

新机器没有 `persona-agent` 用户时创建一次，然后在项目目录安装依赖并安装服务：

```bash
sudo useradd --system --user-group --home-dir /var/lib/persona-agent --no-create-home --shell /usr/sbin/nologin persona-agent
cd /opt/persona-agent
sudo npm ci --ignore-scripts --no-fund --no-audit
sudo chown -R root:root /opt/persona-agent
sudo chmod -R a+rX /opt/persona-agent
sudo /usr/bin/node node_modules/playwright/cli.js install-deps chromium
sudo install -d -m 0700 -o persona-agent -g persona-agent /var/cache/persona-agent-browsers
sudo -u persona-agent env PLAYWRIGHT_BROWSERS_PATH=/var/cache/persona-agent-browsers /usr/bin/node node_modules/playwright/cli.js install chromium --only-shell
sudo install -m 0644 deploy/persona-agent.service /etc/systemd/system/persona-agent.service
sudo systemd-analyze verify /etc/systemd/system/persona-agent.service
sudo systemctl daemon-reload
sudo systemctl enable --now persona-agent
sudo systemctl status persona-agent --no-pager
```

只对这个新部署、仅包含程序代码的 `/opt/persona-agent` 目录执行上述权限命令。已有数据应迁移到 `/var/lib/persona-agent`，不要将私密数据设置为所有用户可读。服务的 `StateDirectory` 会创建归 `persona-agent` 所有、权限均为 `0700` 的数据目录和独立备份目录；`CacheDirectory` 管理独立浏览器缓存。`ProtectSystem=strict` 使程序目录只读，数据、备份、浏览器缓存和隔离的临时目录保持可写。备份恢复密码与服务机凭据仍应由创建人保管。

模板设置 `PLAYWRIGHT_BROWSERS_PATH=/var/cache/persona-agent-browsers`，并保留 `NoNewPrivileges=yes`；没有禁止 Chromium 所需的用户命名空间。宿主系统仍须允许普通用户创建浏览器沙箱。可以先在项目目录用实际服务用户检查无界面浏览器启动：

```bash
sudo -u persona-agent env PLAYWRIGHT_BROWSERS_PATH=/var/cache/persona-agent-browsers /usr/bin/node --input-type=module -e "import { chromium } from 'playwright'; const browser = await chromium.launch({ headless: true, chromiumSandbox: true }); await browser.close();"
```

这只检查浏览器能否启动。服务启动后，再在后台手动发起一次小黑盒活动，核对实际结果；站点登录或验证码限制仍可能使访问失败。

查看初始化码与日志、停止和重启服务：

```bash
sudo cat /var/lib/persona-agent/setup-key.txt
sudo journalctl -u persona-agent -n 100 --no-pager
sudo systemctl stop persona-agent
sudo systemctl restart persona-agent
```

服务由 systemd 管理时使用 `systemctl`，不要再运行 `start.sh` 或 `dev.sh` 启动第二份进程。systemd 模板等待停止最多 20 秒，且关闭自动 `SIGKILL`；停止失败时先检查日志和进程再处理。升级前先导出加密备份，停止服务，更新程序文件并重新执行 `npm ci --ignore-scripts`；若 Playwright 版本变化，也以服务用户更新同一缓存内的浏览器，最后重启。

## 远程服务器访问

在自己的电脑终端建立 SSH 隧道，将以下示例中的登录名和服务器地址替换为实际值：

```bash
ssh -N -L 3210:127.0.0.1:3210 your-user@your-server
```

保持终端开启，浏览器访问 `http://127.0.0.1:3210`。服务会核验 HTTP Host，因此本地隧道端口也须使用 `3210`。如果本机已有 Memoria，占用同一端口，先停止本机实例。无需公开 `3210` 端口或修改服务监听地址。QQ 协议端推荐部署在同一机器，通过回环地址连接；Windows NapCat 不能直接通过自身的 `127.0.0.1` 连接另一台 Linux 服务器。

## 跨平台迁移

从旧实例后台导出 `.pab` 加密备份，在目标系统安装相同或兼容版本，初始化新管理员后预览并恢复。备份内容是加密的结构化 JSON，由目标系统重建 SQLite 数据，适合 Windows 与 Linux 之间迁移。恢复后需重新填写模型与平台凭据、核验账号绑定并开启外部接入；不要在程序运行中只复制单个 `.sqlite` 文件，以免遗漏 WAL 中的数据。

0.3.65 起写入压缩加密格式 2：gzip 后使用 AES-256-GCM 加密，原始 JSON 最多 128 MiB、完整 `.pab` 文件最多 30 MiB，两项均须满足；数据超限时失败，不截断或删除内容。新文件须使用 0.3.65 或兼容的更新版本恢复，仍兼容读取旧格式 1，内部数据结构仍为版本 5。压缩算法和原始字节长度受加密认证保护，恢复时认证通过后才有界解压。手动导出、自动本地及 WebDAV 备份、恢复前快照均使用这一格式，WebDAV 仍校验上传与回读的加密文件字节一致。

导入仍受单类 10 万、合计 25 万条记录及各字段格式限制，预览只显示解密后数量，不保证全部记录可恢复。大备份的生成和恢复在本机同步进行，会增加瞬时内存占用并暂时延迟其他请求；升级前保留一份已验证可用的旧备份，迁移时先更新目标程序再恢复新格式。

创建人上传的表情、QQ 收藏的表情图片、各自可用范围和删除记录随加密备份迁移；这些个人图片不进入公开源码。内置表情随程序源码分发。浏览器二进制不在备份中，须在目标系统另行安装；不要把 Windows 的浏览器缓存复制给 Linux 使用。

书籍正文、阅读位置、已保存的笔记和聊天约定也随加密备份迁移。目标系统恢复后，先核对书房和账号绑定，再按需重新开启自主读书、自主浏览、自主表达、主动私聊与自动备份。未发送的有效约定会暂停，重新绑定 QQ 后，仍需在聊天中明确恢复；不要把开启主动私聊当作恢复了所有约定。

小黑盒自主选文会按需参考最多三条未改动的公开阅读笔记，延续其中的疑问；与创建人兴趣共用一次选文判断，不新增日程或提高活动次数。使用后台配置的模型和每日 200 次总额度，没有依据时不调用选文模型。私人书籍、群聊笔记或无法核验公开来源的记录不会进入这组旧笔记。笔记及原阅读有过修订，即使后来恢复相同正文，也不作为这组连续阅读依据；这些来源、修订与活动依据 ID 随现有加密备份保存。

0.3.33 的备份数据结构为版本 5，新增聊天约定，仍兼容导入结构版本 1–4。版本 4 起包含对话来源屏蔽记录。恢复时合并本实例已有的屏蔽记录，较早备份不会解除这些来源在模型近期历史和对话检索中的屏蔽。恢复仍会替换书架正文，不能据此认为所有后续修订都会保留。版本 5 备份请使用 0.3.33 或兼容的更新版本恢复。

0.3.22 起，助手回复直接关联当次参考的历史助手消息，持续主动聊天也能保留撤回依赖而不反复复制全部旧来源。保留这种引用传播行为需要使用 0.3.22 或兼容的更新版本恢复。

## 读书与自主表达配置

书房支持 UTF-8 TXT（单个不超过 3 MiB、100 万字符，超过任一上限请分章导入）和单个 HTTPS 网页正文；最多保存 10 本，正文合计不超过 5 MiB。创建人可在绑定 QQ 的私聊中发送 TXT，或明确提供本条消息中的网址让她收录；也可在后台上传或导入。QQ TXT 自动收书和后台导入本身不调用模型，通过聊天导入网址会使用正常的模型工具调用与回复额度。收录不会将整本正文写入聊天记录。群聊不可访问创建人的私人书房。

启用自主读书后，默认每天最多 2 次、每次约 3000 字符，在 `Asia/Shanghai` 时区的 09:00–23:00 随机安排，可在后台调整。每次笔记输出最多 700 tokens，与聊天共用模型额度。服务停止时不会阅读；在线导入只收录当前页，不追抓整站或其他章节。创建人日常可通过聊天查书架、阅读位置、笔记，或指定一本书读一小段。聊天阅读无需开启自主读书，与手动、定时阅读共用每日读书额度和单次长度，不受定时活跃时段限制。

聊天导入或继续阅读只依据当前正文的明确请求，引用、代码、否定、未来打算或单独网址不作执行要求。完整 HTTPS 网址请与说明文字用空格、括号或换行分开。继续阅读先核对本轮列表中的唯一书名或 ID；只有一本候选时可说“读一小段”，多本时需明确选择。查询进度和已有笔记不会推进阅读；每轮阅读与导入合计最多尝试一次，失败也计入。图片里的文字或网址不提供操作授权，附图时仍可按明确的正文请求处理。

有可用读书额度时，明确的聊天读书请求可取消正在进行的自主读书，并最多等待 2 秒结束后再读所选书；期间不会插入另一项后台或手动阅读。旧任务未及时结束时仍保持忙碌，迟到的旧结果不会保存；已有手动或聊天阅读不被抢占。取消的读书尝试与已经发出的模型请求均不退回，额度用尽时不为新请求取消仍在进行的旧阅读。聊天取消、书籍或配置变化、服务停止时，等待中的请求也不会继续启动阅读。

连续阅读会从同一本书的真实阅读记录中，取最多三条有效旧笔记作为背景，每条最多 1000 字符，截断会明确标记；不会额外调用模型整理背景。修改过、删除的笔记和其他书籍不参与，旧笔记也不能当作原文事实或未读章节。相关笔记或书籍在生成期间变化时，不保存该结果或推进进度，尝试仍计次。旧笔记、来源记录和阅读进度随现有加密备份保存，重启后仍可继续；不新增会话历史依赖。

0.3.46 起，新笔记记录实际使用的旧笔记关联，网页读后思考也关联本次原文。更正或忘记来源时，依赖旧版本且仍未人工修订的派生笔记会递归移出书架并留下删除标记；阅读位置、原始经历和人工修订后的笔记保留。聊天通过书房工具取得的笔记会成为本轮回复的来源，生成期间变化会停止使用，后续更正或忘记也会屏蔽引用旧版本的回复。

这些关联随现有结构版本 5 加密备份保存；含此类关联的备份应使用 0.3.46 或兼容的更新版本恢复。恢复时保留本机已有删除标记及阅读、笔记的修订证据，即使较早备份没有原条目，也不会丢掉本机已知的更正证据；失效来源的派生笔记不会重新进入检索。旧版未保存的旧笔记关联无法可靠回填，不能据此保证撤回所有旧派生内容。网页思考期间修改人格、模型或相关旧笔记时，本次思考取消，已完成的原文阅读保留，实际模型尝试仍计次。

0.3.48 将回复的版本关联扩展到实际参考的各类记忆，用于普通聊天、DSH 记忆检索、主动私聊和 B站评论回复。生成期间修改来源会取消结果；后续更正或删除会使引用旧版本的回复退出模型历史与对话检索。更正后的正文仍可用于新回复；只读取独立用户原话，不会继承该轮失效助手回复的依赖。旧回复缺少版本记录但已有条目修订证据时会保守隐藏，未记录的引用无法可靠回填。

自主表达在生成与发送前核对实际使用的阅读、笔记和本人动态。提交后才失效时仍记录实际提交结果，失效正文不再另存为新的书架依据；不会自动删除已发布的平台内容。已用判断和发送尝试仍按原规则计次，不增加模型调用或额度。

含这些版本关联或普通记忆修订证据的备份应使用 0.3.48 或兼容的更新版本恢复，结构版本仍为 5。恢复合并本机已有的所有记忆修订证据，含旧备份尚未收录的条目，并校验冲突与容量；正文仍按恢复的数据集替换。新机器只知道备份本身带有的证据，不能据旧备份获知后来的更正。

小黑盒和 B站的读后思考都可参考此前最多三条有效的公开阅读笔记，每条最多 800 字符，截断会标明。旧笔记须来自可核验的 B站或小黑盒公开阅读，私人书籍、聊天和手工记录不参与；没有合适旧笔记时只使用当次摘录。她可以延续旧问题或修正想法，不会把旧观点当作原文事实，也不代表重新读过旧资料全文。新笔记关联本次原文及实际参考的旧笔记，沿用来源更正、遗忘和备份规则；生成期间相关资料或人格、模型配置变化时不保存结果，已完成的原阅读保留。

自主表达与阅读分别设置。QQ 支持空间动态、签名和头像，需要协议端提供相应能力；Windows 上的小黑盒发帖、评论与回复需要已配置并登录的[专用 MuMu 设备](android.md)，评论和回复另需 Google Android CLI 与 SDK Platform Tools。各平台与动作可分别开关，评论和回复默认关闭。发帖、评论与回复共用每天 80 次的默认总额度，可自定义 0–100，同时受各平台上限、时段和间隔约束；失败和结果未确认也计次。模型可以选择安静，80 次并非必须完成的任务。Linux 核心服务目前没有小黑盒客户端发布适配。绘图 API 只保留配置入口，尚不调用；保留密钥为空不影响现有聊天、阅读和内置表情。

## B站视频评论通知回复

此项默认关闭，需要另行配置独立社交宿主，以及带有效社交凭据的栖忆专用 B站账号。视频读取可继续匿名或使用旧的只读凭据；保存登录状态不会开启回复，也不会把专用执行账号认作创建人。

### 安装独立社交环境

准备目标系统的 Node.js 24、Python 3.10 或以上、可用的 `venv` 模块、系统 `tar` 命令和网络连接，并用运行 Memoria 的同一系统账号安装。Linux 缺少 `venv` 时，先安装发行版中与所选 Python 对应的虚拟环境支持；不要求系统已装 pip 或 ensurepip。下面在 Memoria 程序目录执行；路径是示例，须替换为本机实际路径。

安装目标必须是现有父目录下尚不存在的绝对路径，放在程序源码和个人 DSH 配置之外。安装器只创建这个独立环境，不改项目数据、平台开关或账号，不读取浏览器凭据。

Windows PowerShell：

```powershell
& "C:\path\to\node24\node.exe" .\scripts\install-bili-social.js --directory "C:\path\to\memoria-bili-social" --python "C:\path\to\Python312\python.exe"
```

Linux：

```bash
/path/to/node24/bin/node ./scripts/install-bili-social.js --directory /path/to/memoria-bili-social --python /usr/bin/python3
```

安装器下载固定的 [`dsh-bili-subagent` 0.7.7 原包](https://github.com/Yuuyuko-uu/dsh-bili-subagent/tree/bbe41848137cdfa334bf04ebe7d5d29830390923)，核对归档与原 MCP 文件后保留完整包，并建立独立 Python 虚拟环境。Python 依赖使用项目的 `deploy/bili-social/requirements.txt` 固定版本，其中 `bilibili-api-python` 为 17.4.2、`mcp` 为 1.26.0；不要自行替换为最新版本或复用已有虚拟环境。这里复用原 MCP 客户端与服务，不启动原插件的整套 DSH bundle、自动刷片、私信或 @ 功能。

安装完成后会输出 `installed: true` 和 `configuration` 对象，默认 `enabled: false`。将这个对象保存为下一节的本机配置，使用 UTF-8 无 BOM 的 JSON 文件，不要把整个输出外层对象一起保存。若安装未完成，先核对提示和依赖；重装应选择新的独立目标目录，避免覆盖已有环境。原插件采用 MIT；外部 Python SDK `bilibili-api-python` 采用 [GPL-3.0-or-later](https://pypi.org/project/bilibili-api-python/17.4.2/)。原包、依赖及其许可证保留在独立环境，不随 Memoria 源码或加密数据备份分发。

### 配置与启用

独立环境的本机配置文件是数据目录下的 `bili-social-runtime.json`，与视频读取使用的 `dsh-runtime.json` 分开；示例路径须替换为目标系统上的实际绝对路径：

```json
{
  "enabled": false,
  "nodePath": "C:/path/to/node24/node.exe",
  "hostDirectory": "C:/path/to/memoria-bili-social/host",
  "pythonPath": "C:/path/to/memoria-bili-social/venv/Scripts/python.exe"
}
```

Linux 使用安装器输出的本机 Node.js、`host` 和 `venv/bin/python` 的绝对路径；保留虚拟环境的解释器路径，不改成系统 Python 或其解析后的链接目标。systemd 部署时用服务账号安装，将独立环境放在该账号可访问的目录，例如已有的 `StateDirectory` 内。两个系统分别安装依赖，不复用 Windows 的 `node_modules` 或 Python 虚拟环境；WSL 应使用 Linux 文件系统中的独立环境。

先在下方 B站登录说明中保存专用账号凭据。旧文件只支持阅读时，重新加载 Chrome 登录桥 1.1.0，再点击导入。核对安装和专用账号后，将配置中的 `enabled` 改为 `true`，再开启下面的平台回复选项；关闭此文件开关可停止新的社交任务，不影响已有只读视频配置。后台显示本机凭据、环境是否就绪和暂停状态；环境就绪不证明平台登录仍有效，真实账号和目标会在执行前再次核对。

在“人格与设置 → 自主表达”分别勾选“允许在 B站自主表达”和“回复视频评论通知”，并设置 B站每天通知回复上限，范围 0–100，默认 80。还须开启总的自主表达开关；沿用表达欲、活跃时段、机会间隔和所有平台合计的每日上限，不会另起一条无限自动回复流程。设为 0 或关闭任一开关即停止新的 B站回复。

每个表达机会最多读取 20 条回复通知，只考虑七天内且能核对专用账号、视频与评论来源的条目。当前只处理视频评论回复，不处理 @、私信、动态，不主动在新视频下评论，也不根据网友自称改变创建人身份。模型可以保持安静；选择回复时正文最多 200 字，只能回应本次已经核对的评论，不能改换目标或账号。

公开交流背景只使用当前评论线程和公开书架，不读取创建人私聊或其他群聊。取得回复编号后，对方原评论、来源及已回复状态存入该线程的书架；自己的完整回复保留在带来源关联的对话档案，后续检索沿用资料更正与遗忘的过滤规则。这些有限记录可用于相同线程的后续交流，不等于拥有对方所有平台的私人记忆。平台凭据不进入模型。没有看过的视频不能因收到评论通知就声称已观看。

0.3.57 起，B站回复生成可使用五个只读工具：搜索书架、读取正文、核对原话、搜索已完成对话及读取对话。搜索每页最多 6 条，正文每页最多 4000 字，可按返回的下一页位置继续查找。当前通知本身不冒充已完成旧对话；范围始终固定为本评论线程和公开书架。工具参数不能改换账号、场合或发布目标，旧资料中的指令也不能授权操作。

每个判断机会最多 4 次模型请求、5 次只读工具，最后一次请求不开放工具，上下文合计最多 80000 字符；每次实际请求计入原有每日 200 次模型额度。查询更多旧资料仍属于同一次表达判断，只有实际进入提交阶段才消耗相应发布尝试。工具预算或格式校验失败时停止本次机会，不转为另一次回复重试。普通平台表达仍沿用一次模型请求的原流程。

实际使用的书架版本、原话及历史对话会关联到本次助手回复。资料在生成中或发送前更正、删除、屏蔽或变得不可见时，停止发送；之后更正相关资料，引用旧版本的回复会退出后续可用历史。记录关联不保证识别所有换句话说的重复事实，也不会撤回平台已经提交的内容。

同一通知在开始判断后持久记账，安静、失败、取消或结果未确认都不会自动重试。实际提交前核对通知和配置，并与 QQ、小黑盒共用全平台默认每日 80 次公开表达预算；每次表达判断仍共用每日 200 次模型请求。后台的提交回执只证明平台返回了回复编号，不证明审核通过、公开可见或对方已读；`unknown` 不自动重发。已有发送在途时无法保证撤回。

### 平台暂停后的维护

账号或平台限制会留下本机暂停标记，重新导入登录不会自动解除。只有确认平台已恢复后再维护：

1. 关闭 B站自主表达，并停止 Memoria 服务。
2. 在 B站官方客户端确认专用账号登录有效、平台已恢复且没有待处理验证；未完成时保持暂停。
3. 删除本机数据目录的 `bili-social-pause.json`（默认位置为 `data/bili-social-pause.json`），再启动服务。
4. 核对状态后，按需重新开启 B站自主表达和通知回复。

此操作不处理或跳过平台验证，不清零已用额度，也不会让已判断或结果未确认的通知重新发送。平台仍拒绝请求时会再次暂停；无需通过更换账号恢复。

## DSH 只读插件接入

此功能可选。核心服务仍使用 Node.js 22.16 或以上；独立插件宿主需要 Node.js 24。目前固定支持 DSH `0.2.1-rc.2` 与 `dsh-bili-humanism` `1.7.0`，另可按下文分别配置 `dsh-speak-up` `0.2.2` 用于主动搭话、`dsh-feiyu-mood` `0.4.3` 用于对话心情评估；不扫描或自动启用其他插件。可以在 Windows 或 Linux 配置对应系统的 Node.js 路径。

在项目和个人 DSH 配置之外建立专用宿主目录。下载作者 [1.7.0 发布页](https://github.com/InariNGT-Ofiicial/dsh-bili-humanism/releases/tag/v1.7.0) 的 `dsh-bili-humanism-1.7.0.tgz`，在专用目录使用 Node.js 24 附带的 npm 安装：

```bash
npm init -y
npm install --ignore-scripts --save-exact @deepseek-ai/dsh@0.2.1-rc.2 /absolute/path/dsh-bili-humanism-1.7.0.tgz
```

将示例中的包文件路径换为实际下载地址。在 Memoria 的数据目录创建 `dsh-runtime.json`（默认数据目录为项目中的 `data/`）：

```json
{
  "enabled": true,
  "nodePath": "D:/tools/node24/node.exe",
  "hostDirectory": "D:/tools/memoria-dsh-host"
}
```

Linux 可分别填写 `/opt/node24/bin/node` 和 `/var/lib/persona-agent/dsh-host` 等实际绝对路径。Memoria 服务用户须有执行 Node 和写入专用宿主目录的权限。使用仓库 systemd 模板时，宿主放在可写的 `StateDirectory` 内；其他位置还须加入该服务的 `ReadWritePaths`。此文件仅由部署者在本机设置，不接受聊天或插件修改路径。无需在 DSH profile 中填写模型密钥或复制个人配置。

使用 WSL 时，将 Linux 宿主及其 `node_modules` 安装在 Linux 文件系统，例如 `~/memoria-dsh-host`。从 `/mnt/c` 或 `/mnt/d` 加载大量依赖可能导致启动超时；不要复用 Windows 的宿主依赖目录。

在后台“人格与设置 → DSH 插件运行层”点击检测。此按钮启动独立子进程，核对真实插件注册及只读开关，不调用模型或平台；结束后关闭宿主并清理临时 profile。关闭方法是将 `enabled` 改为 `false` 或移除配置文件，无需改变聊天与书架设置。

启用后，可以在聊天中提供完整的 `https://www.bilibili.com/video/BV…/` 链接让她读取视频文字，也可使用“网页阅读”或把链接加入固定网址阅读安排。支持 `?p=2` 等 1–100 的分 P 参数，分享追踪参数会移除；不解析短链。不下载视频、不抽帧或执行 ASR；平台未返回字幕时不会保存为已读，不能凭标题或搜索摘要补写内容。

部分字幕需要登录。在“人格与设置 → DSH 插件运行层”点击“登录 B站专用账号”，由你在项目独立浏览器里手动登录，然后回后台点击“完成登录，保存状态”。Windows 使用已安装的 Google Chrome 独立资料目录，不读取日常浏览器登录；Linux 需要图形会话和完整 Chromium（`npx playwright install chromium`）。无图形会话的 Linux 服务当前无法完成本机交互登录，可以先匿名使用。这里保存的是栖忆的执行账号，不会把它绑定成创建人。

也可以导入当前 Chrome 中已有的 B站登录，无需在自动化窗口重新登录：

1. 在已登录 B站的那个 Chrome 资料中打开 `chrome://extensions`，启用开发者模式，选择“加载已解压的扩展程序”，加载本项目的 `extensions/bili-login-bridge` 目录。
2. 用同一个 Chrome 打开 `http://127.0.0.1:3210` 并登录创建人后台。在“人格与设置 → DSH 插件运行层”点击“从当前 Chrome 导入 B站登录”。看到已保存提示后即可移除扩展。

登录桥 1.1.0 只在点击时读取 `www.bilibili.com` 下的 `SESSDATA`、`DedeUserID`、`bili_jct` 和可用的 `buvid3`，经已登录的本机后台保存；不读取浏览历史或其他网站，不执行自动同步，导入过程不向模型或其他服务传送登录状态。升级项目后，已装扩展须在 `chrome://extensions` 重新加载，确认版本 1.1.0，再点一次导入。旧文件仍可用于只读；社交回复需要有效 `bili_jct`，不能只看“已保存”。扩展只接受来自上述本机地址的请求，其他端口、远程地址和内置浏览器不能使用此导入按钮。退出 Chrome 的 B站登录后，本机副本不一定立即失效，请在 B站账号管理中撤销不再使用的会话。这里不读取 Google 登录、不复制或解密 Chrome 资料目录。[Chrome 扩展加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-an-unpacked-extension)

专用浏览器资料留在数据目录的 `bili-browser/`；本机执行凭据保存到 `bili-credentials.json`，不进入 GitHub、结构化备份、模型消息或字幕域请求。视频读取通道只取得所需的只读字段，只向固定 B站只读 API 携带 SESSDATA，不因此获得评论或其他写入功能；视频评论通知回复需另配[独立社交通道](#b站视频评论通知回复)。后台分别显示只读与社交凭据是否齐备，仅表示本机保存情况，不证明平台认证仍有效；失效后可重新登录。登录不会自动解除已有风险暂停。

新读取由栖忆统一登记尝试：默认每天 6 次，所有场合共用，后台可调整为 0–50，按 UTC 日期计数。失败、无字幕和进程启动失败也计次；检测与翻阅已有书架不计次，重启或换 DSH 会话不清零。固定网址计划还遵守其原有间隔和每日次数。单次采集受插件 90 秒、最多 12 个网络请求约束；字幕文字上限 600000 UTF-8 字节，超限明确失败，不截断后声称完整获取。聊天后续理解与回复继续使用栖忆已配置的模型和每日模型额度，字幕取稿本身不调用模型，也不占公开发布的 80 次额度。

取得的文字带时间戳、来源与覆盖说明，按最多 50 段、每段不超过 30000 字原子存入书架；任一分段失败都不留下半份成功记录。搜索或翻阅任意有效分段时，可取得同次资料的分段索引，逐段继续阅读。保存全文表示留存本次取得的全部文字，不表示观看画面、听过声音或覆盖完整视频。书架分段及其索引、来源随栖忆加密备份迁移。

要让她自行发现内容，在“自主浏览”来源中勾选 B站并启用日程。小黑盒与 B站可单独或同时选择，共用每天的随机活动机会；旧配置保持只选小黑盒。每次 B站活动先读取最多三条热门候选，再由栖忆在本机按配置兴趣、人格关键词、未读记录与失败冷却选择一条；只把所选网址交回 DSH，不将私聊或人物记忆发送给平台。发现和取稿共用一次 DSH 每日尝试，原生宿主全程最多 12 次网络请求；没有未读候选便保持安静，失败视频冷却 24 小时，不在同次活动中换片重试。

成功取得文字后，先把全部分段存入栖忆书架，再通过 DSH 原生模型接口写笔记。此笔记任务取得当次公开文字的前 8000 字符、来源与覆盖说明，可同时参考上述最多三条公开阅读旧笔记，不携带私人笔记、聊天、平台凭据或模型密钥。栖忆加入当前人格资料，使用后台配置的模型完成一次纯文本请求，最多输出 650 tokens；与聊天共用每日 200 次模型请求上限，失败与取消也计入尝试，不重试或改用另一条模型链。插件不能选择模型服务地址、覆盖密钥或调用写入工具。

笔记存回栖忆书架，不依赖 DSH 会话。笔记失败或额度用完时保留已保存的阅读正文；笔记任务不重复取稿，也不再占用 DSH 阅读尝试或公开表达的 80 次额度。分段正文全部保存不表示模型当次读过所有文字；笔记会保留资料覆盖说明。创建人私聊中说“现在去B站逛一下”也可触发一次，仍须已启用 B站来源并受相同额度限制；指定小黑盒时只浏览小黑盒。普通问候、询问过去是否读过或引用里的请求不会触发新的 B站活动。此读取通道只浏览、取文字和记笔记，不执行 B站公开表达。

采集缓存和平台风险暂停持久保存在数据目录的 `dsh-cache/humanism/`，跨子进程共用；不要通过删除缓存或换会话绕过平台暂停。缓存属于执行状态，不包含在结构化记忆备份中；机器路径配置也不会随备份迁移，新实例须核对目标平台访问情况后再配置。此只读宿主不开放评论、语音或其他未经接入的 DSH 插件；可选主动搭话的安装见下文。

DSH 通过栖忆提供的搜索、分页正文和来源工具读取当前场合获准使用的记忆。场合与发言者由栖忆确定，工具参数不能指定或扩大权限。每次读取查询当前书架；换会话或重启宿主不会清空已存记忆。长期记忆、来源、修订和删除记录继续进入栖忆加密备份，临时插件缓存不属于备份内容。单次模型上下文仍有限，保存的信息需按问题检索和分段读取，不保证一次调用回想所有经历。

0.3.49 起，普通聊天与 DSH 的历史对话检索都支持日期范围，可用于“昨天聊过什么”或指定日期的回想。日期按后台主动私聊时区解释，默认 `Asia/Shanghai`，无需开启主动私聊。筛选依据是用户原话的记录时间，起止日期均包含当天；有关键词时在该时段内检索，只有日期时可直接分页。结果继续使用原身份范围、来源屏蔽和版本撤回规则，未完成或缺少关联的记录仍可能不可检索。日期范围只定位已保存的对话，不会触发平台浏览或自动整理新的事实。

0.3.50 起，对话检索可进一步限定创建人私聊的平台，目前支持 QQ 与飞书，并可与日期、关键词和分页组合。摘要和正文提供核对过的历史平台标签；来源缺失、只有单侧记录或相互冲突时不归类，也不从正文、群号或发言者标签猜平台。未指定平台时仍可检索这些旧记录，因此指定平台查不到不能断言从未聊过。恢复备份或解除当前绑定不会抹掉完整的历史来源标签，也不会据此恢复任何绑定或发送权限。群聊等场合继续使用原有可见档案，不能通过平台筛选读取创建人私聊。

聊天和 DSH 搜索每页最多提供 6 条匹配及当前可见的命中总数，可以继续翻查后续页，再按记忆 ID 读取正文或核对原话。较早记录不再因排在首屏之外而无法取得索引；需要时可以在聊天中要求“继续查同一主题的更早记录”。搜索结果的位置按条目计数，正文和原话的位置按字符计数，二者分别翻页。搜索只统计获准范围内未删除的记录；修改、删除后结果立即反映当前书架，排序变化时需从第一页重新核对。每轮聊天仍最多调用 5 次工具，不会为了列完书架自动增加整轮模型预算，也不表示一次对话能读完全部长期记忆。

书架没有收录的细节可通过 `search_conversations` 查找历史对话，再用 `read_conversation` 分段核对，每页分别最多 6 轮和 4000 字符。检索不依赖最近 16 条消息仍在模型上下文内，且不额外调用模型整理档案。用户原话、助手旧回复和各自时间分别标明；助手旧话可能有误，不能当成用户事实。旧版记录只要保留明确、有效的消息与回复关联，也能提供已完成轮次；缺少关联或未完成的记录不猜测匹配。创建人私聊、其他私聊和群聊沿用各自可见范围，模型不能通过参数指定另一场合。

修订或忘记对话来源记忆后，关联原轮次不再进入档案检索和模型近期历史；引用了被屏蔽来源的助手回复也会隐藏，独立用户原话仍保留。旧版来源缺少消息 ID 时，同一场合、同一发言者的相同原话会一并屏蔽。恢复备份后若删除或修订证据仍在、对应来源已缺失，该场合无法确认来源的旧记录会暂不提供；有完整来源关联的新记录仍可使用。依赖按实际读取和近期历史记录，不保证识别未关联的重复事实。原始聊天和事件仍保存在本机；有效书架条目的来源核对保留，便于比较原话和当前修订。

聊天更正或忘记成功后，会返回简短确认并结束本轮处理，不复述条目标题、正文或附带表情；同一句中的其他请求请另发消息。成功确认可进入后续可用历史，更正后再次修改或删除目标条目时，关联旧版本的确认仍会退出可用历史。确认记录不代替当前书架，也不恢复旧原话或旧回复的可见性。忘记仅将条目移出当前书架，原始聊天、经历、修订记录和旧备份仍保留。取消、来源变化或投递未确认时，不保证能保存确认记录，也不会自动重发。

启用上述 DSH 运行层后，聊天还可以按需调用原生记忆子代理，例如“让记忆子代理核对一下最早的约定和原话”。它会建立真实的 agent/session 回合，开放书架搜索、记忆正文、记忆来源、对话搜索和对话正文五种只读工具。栖忆固定当前身份与可见范围，直接取得工具结果并保存模型历史；子代理不能指定其他账号或范围，群聊不会取得创建人的私聊。简单查询仍可直接使用原有记忆工具。

每轮聊天最多尝试一次子代理任务，内部最多 4 次模型请求、5 次记忆工具；第 4 次请求不再提供工具。内部模型请求与外层聊天共用每日 200 次总额度，公开发布和 B站读取分别计数。父进程累计模型上下文最多 80000 字符，超过便终止，不截断后声称已经查完；失败或取消不自动重试。最终回答需与栖忆实际收到的完整模型回复一致，截断回复不会当作成功结果。

记忆子代理或主动拟聊因额度用完、回复格式不符、请求未完成或所用资料变化而停止时，会保留能核实的原因；聊天仍会说明失败不等于没有相关记忆。未知故障显示通用提示，不自动重试。阅读笔记与心情任务也会区分已核实的额度、回复格式和请求失败。

普通记忆子代理会重新核对实际读取或搜索返回的条目、原话、对话及分段索引；修改正文节选之外的内容、删除条目或改变可见范围，也会使本次结果失效。核对覆盖子代理运行、结果回传和后续主聊天回复保存之前；来源变化后停止基于旧结果回答，已经发生的模型调用仍计次。此检查针对子代理使用的资料，不表示普通聊天所有初始资料都已获得相同的持续核对，也不能撤回已经发出的消息。

原生回合结束后释放 agent 并清理临时会话，长期记忆仍在栖忆数据库；新任务重新按范围检索。正常收到 SIGINT/SIGTERM 时会取消并等待当前 DSH 任务清理，强行结束进程无法保证清理完成。此记忆入口不访问平台或写入记忆，也不自动加载其他 DSH 插件、定时器、朗读或第二套 QQ 消息桥。

主动私聊也可复用原生回合。栖忆从过滤后的创建人场合自行核对消息和有限背景，提供统一人格、抽象心情和记录时间；插件不能指定其他场合或收件人。最终只产生一段拟聊文本或选择安静，栖忆再次核对来源、QQ 登录账号和发送上限后决定发送。读取过的记忆正文、原话或依赖在生成后、发送前变化时取消；使用来源的完整记录核对，正文节选之外的修订也会使结果失效。默认使用原生主动拟聊，也可选用下述原版插件触发同一个临时 agent。

## 心情与节奏

在“人格与设置 → 心情与节奏”开启间歇评估，需要已配置 DSH 与模型 API。默认关闭；开启后默认每 180 分钟最多一次、每天最多 4 次，可设置 60–1440 分钟和每天 0–12 次，按 UTC 日期计数。每天设为 0 会停止新评估。关闭浏览器后，运行中的栖忆服务仍会按间隔检查；没有新资料便保持安静。

每次只选最近 24 小时内的一段已完成对话，或一份已保存的小黑盒、B站公开阅读资料。不同私聊或群聊不会合并进同一次评估；引用先在栖忆核对，再将最多 3000 字符的当次文本和最多 1500 字符的回复交给独立 DSH 任务。历史图片不会重新传送。模型使用相同人格和栖忆配置的服务，每次最多一次请求、300 输出 tokens，与聊天共用每日 200 次总上限，不重复占用 DSH 视频读取或公开表达额度。

模型只提出心境值的 -10 至 10 变化、固定情绪和置信度；把握不足、格式无效、取消或原资料改变时不应用。评估失败和取消也计次，同一资料不自动重试，重启或修改设置不清空已用次数。后台“评估一次心情”可提前自动间隔，仍须已开启、有新资料并遵守上限。

心情评估和主动私聊使用与普通聊天一致的来源屏蔽，关联记忆被修订或忘记后，不再以相应旧对话和旧助手回复生成新结果；生成期间资料变化会取消结果。主动私聊仍按真实最近发言计算安静期，来源屏蔽不会缩短等待时间。原始记录仍可在创建人后台查看。

对话、自主表达和主动私聊共用栖忆保存的数值与固定标签，不读取另一场合的私人原因、姓名、引用或关系描述。心境只作语气参考，不改变平台开关、表达欲、安静时段或发布额度。它表示角色状态，并不证明真实感受或实际发生的经历。

未评估时初始值为 70、情绪为平静；数值偏离按 3 小时半衰向 70 回稳，六小时后标签回到平静。回稳在本机计算，不调用模型。状态及评估事件随加密备份迁移；恢复后新评估暂停，运行配额和模型凭据不从备份导入。

默认使用栖忆原生心情评估，设计灵感参考[鱼的心情](https://github.com/Yuuyuko-uu/dsh-feiyu-mood)。也可按下文安装原包，使用其真实对话钩子和判定算法；统一心情仍由栖忆保存，不导入个人 DSH 会话、配置或状态文件。

### 可选表情关键词检索

先完成上述独立 DSH 宿主安装，再在该宿主目录安装 [`dsh-meme`](https://github.com/yyh-001/dsh-meme) 固定版本：
