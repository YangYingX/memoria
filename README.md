# 栖忆 · Memoria

一个拥有持续人格与长期记忆的 AI 伙伴。你可以管理她的人格、记忆和账号，让对话与阅读经历持续积累。项目正在开发中。

| 类别 | 当前支持 |
| --- | --- |
| 部署环境 | Windows、Linux |
| 聊天渠道 | QQ 私聊、群聊；本机管理后台 |
| 模型服务 | DeepSeek 等兼容 Chat Completions 与函数工具的 API |

默认人格名为“未央”，可在后台修改。项目名称与人格名称相互独立。

## 安装与启动

需要 Node.js 22.16 或更高版本。下载仓库源码，解压后在项目目录安装依赖：

```bash
npm ci --ignore-scripts
```

Windows 使用 PowerShell 时可执行 `npm.cmd ci --ignore-scripts`。

使用小黑盒自主浏览前，还需要安装独立的 Chromium 阅读浏览器：

```bash
npm run browser:install
```

这会安装 Chromium headless shell，不使用你的日常浏览器账号。Windows PowerShell 可用 `npm.cmd run browser:install`；Linux 还需系统依赖，见[部署说明](docs/deployment.md#自主浏览器安装)。仅聊天和普通网页阅读不需要下载浏览器。

- **Windows**：双击 `start.cmd` 后台启动，双击 `stop.cmd` 停止。
- **Linux**：执行 `bash scripts/start.sh` 后台启动，执行 `bash scripts/stop.sh` 停止。
- 打开 [本机管理后台](http://127.0.0.1:3210)。首次使用时，填写 `data/setup-key.txt` 中的初始化码并设置至少 12 位的管理密码。

服务器安装、独立数据目录、systemd 和远程访问方法见 [安装与部署说明](docs/deployment.md)。

## 开始使用

后台主要用于首次配置、查看记录和管理数据。完成模型配置与创建人 QQ 绑定后，日常交流、收书、询问阅读进度和笔记都可以在 QQ 私聊中进行。

1. 在聊天页输入 `记住：我喜欢爵士乐`，再询问“我喜欢什么音乐”。未配置模型时，这是明确标记的离线演示，用来验证存储和检索。
2. 切换群聊调试场景，查询同样的话题：创建人的私密记忆不会进入群聊上下文。
3. 在记忆书架添加、修改、删除记忆，查看来源和修改历史。
4. 在阅读页输入公开文章网址。成功提取正文才写入阅读事件和记忆。
5. 在设置中填入模型 Base URL、模型名、API Key，保存后点击“测试模型连接”。留空 API Key 保留已有密钥；明确勾选清除才能回到演示模式。默认 DeepSeek 地址为 `https://api.deepseek.com`、模型 `deepseek-flash`，以非思考模式进行自然交流和工具调用；也支持提供 Chat Completions 和函数工具的其他兼容服务。普通聊天模型不支持工具时，需选择对应的工具模型。测试会产生一次短模型请求费用。
6. 导出加密备份，先预览再恢复；恢复前自动生成加密回滚文件。

## 当前能力与边界

- 创建人后台：通过密码访问，可管理人格、账号和所有场合的记录。
- 统一人格：在不同聊天场合使用同一人格设定，并按场合调用有权访问的记忆。
- 记忆书架：查看和搜索记忆、核对时间与来源、修改内容或删除条目，并保留修订记录。
- 对话与记忆：模型可以检索和保存当前场合的记忆，并阅读你在本次消息中提供的完整公开网址。一次对话不保证读完整条长记忆。每天最多 200 次模型请求，按 UTC 日期计数，费用由模型服务商收取。
- 群聊调试：与创建人私聊使用不同历史和记忆。`public` 内容可被所有场合检索，发布前请确认内容适合公开。
- 网页阅读：HTTP/HTTPS 公共地址、正文提取、来源记录；限制重定向、超时和正文大小，拒绝本机及内网目标。一次提取最多 30000 字，已提取正文完整保存到经历记录与可检索书架；模型先获取节选，再按需搜索或翻阅其他位置。每次阅读保留独立经历；同一可见范围、来源网址、标题和正文均未变化时复用有效的书架记忆。普通网页阅读器提取 HTML 或纯文本；小黑盒自主浏览另用独立浏览器加载公开页面的脚本内容。当前不支持登录态访问及音视频理解。
- 固定网址阅读：按设置的网址列表轮流读取；默认关闭；5–1440 分钟间隔，每日 1–20 页，失败也计入预算（UTC 日期）。
- 自主浏览：目前支持小黑盒公开社区。默认关闭；开启后按兴趣选择未读帖子，默认在 `Asia/Shanghai` 时区的 09:00–23:00 内每天随机安排 3–6 次尝试。次数、时区、活跃时段和兴趣可调整；失败也计入额度，成功读取正文后才留下阅读记忆。它与固定网址阅读分别设置。
- 读书：创建人可以上传 TXT 或导入单个 HTTPS 网页正文，保存阅读进度和笔记。自主读书默认关闭；开启后默认每天最多 2 次，每次约 3000 字符，随机安排在 `Asia/Shanghai` 的 09:00–23:00。聊天中也可以查询书架、进度、笔记，或指定一本书读一小段。
- QQ：支持私聊、群聊及图文消息。需另行安装并登录 OneBot v11 协议端，在后台配置账号和白名单；默认关闭。识图需要所选模型支持视觉输入。
- 表情：附带 60 张内置人设主题的透明背景表情，包含中文文字和日常情绪。模型根据语气选择，每次最多一张。创建人可上传自有图片供各聊天场合选用；从 QQ 对话自主收藏的表情仅在原私聊或原群复用，均可在后台查看、删除。
- 自主表达：开启后可在配置的时段内选择安静，或执行已允许的 QQ 空间动态、签名和头像动作。表达欲、次数、间隔及各项动作均可设置；实际结果依赖协议端支持。目前尚未接入其他平台的发布能力。
- 绘图 API：目前只提供服务地址、模型、密钥和额度的预留配置，尚不发起绘图请求；内置表情已随程序提供。
- 备份：手动导出/恢复与定期本地加密备份，可选 WebDAV 上传并回读校验。默认关闭，需配置备份口令；本地保留版本数与执行状态在后台可见。

## QQ 接入

协议端应与本服务运行在同一台机器，支持 OneBot v11 HTTP API 和带签名的 HTTP POST 事件。此仓库不包含 QQ 客户端或协议端，也不直接处理 QQ 密码。

1. 配置本地协议端的 HTTP API，例如 `http://127.0.0.1:3000`，并设置 Access Token。
2. 在后台填写机器人 QQ 号、HTTP API 地址和 Token，设置私聊/群聊白名单。
3. 协议端事件上报地址填写 `http://127.0.0.1:3210/integrations/onebot`。NapCat 的 HTTP 客户端 `token` 填入这里的 Webhook 签名密钥，HTTP 服务端 `token` 对应 Access Token；消息格式选择 `array`。本版使用双 HTTP，不需要 WebSocket。
4. 启用 QQ，在身份绑定页生成一次性验证码。创建人使用自己的 QQ 私聊机器人发送页面提供的 `绑定 ...` 命令，10 分钟内有效。
5. 创建人绑定后，QQ 私聊与本机创建人聊天共用历史。白名单内其他私聊分别隔离；白名单群聊仅在被 @ 时回复，即使创建人在群里说话也不加载其私聊记忆。

模型或消息发送失败后不会自动重发，可在后台查看错误后重新发送。请妥善保管一次性绑定命令，只由创建人本人发送。

“检测 QQ 协议端连接”检查登录与在线状态，不发送消息。配置完成后，请分别通过私聊和群聊发送消息，确认能收到回复。[NapCat 安装说明](https://napneko.github.io/guide/boot/Shell)、[网络配置](https://napneko.github.io/config/basic)。

### 图片与表情

QQ 私聊可以直接发图片或附上问题；群聊需要同时 @ 机器人。支持 JPEG、PNG、WebP、GIF，每条消息最多 4 张、单张不超过 8 MiB、合计不超过 20 MiB。协议端必须提供可下载的公开图片地址。图片获取失败或模型不支持视觉时，会提示失败；识图结论可能有误，可在对话中纠正。

普通图片仅在当轮传给模型，默认不保留原图和临时下载地址。后续对话可以参考先前的文字回复，不能据此重新查看原图；需要核对细节时请重发。要求她记住图片中的内容时，保存的是带来源的文字观察。

创建人可在后台“表情库”上传自有图片，并填写名称和适用情境。管理员上传的图片可供所有聊天场合选择，请只上传愿意在这些场合使用的内容。

她也可以自行收藏适合反复使用的表情包、梗图，每轮最多一张；普通照片、自拍、聊天截图、文档和无法确定的图片不应收藏。QQ 收藏不跨私聊对象、群或平台复用，即使多个账号属于同一个创建人也如此。后台可核对来源和删除。

上传与收藏图片均保存在本机私有数据中，并纳入加密备份，不会上传到项目 GitHub。单张上限 2 MiB，上传与收藏合计最多 8 MiB、64 张；同一 QQ 私聊或群的收藏最多 20 张。内置表情不占这些额度。

### 小黑盒自主浏览

安装阅读浏览器后，在后台“自主活动”中设置兴趣、次数与活跃时段并启用。可查看下一次安排、最近结果，也可手动发起一次浏览。活动需要服务保持运行；休眠或关机期间不会执行，恢复后不会集中补跑所有错过的次数。

小黑盒访问为匿名只读，不使用你的登录账号。需要登录、验证码、页面变更或网络受限时，该次活动可能失败，不会绕过验证，也不会把失败记成已经读过。每日次数是尝试额度，不保证每次都能读到帖子。成功阅读的记录默认供创建人使用。

### 通过聊天收书与读书

创建人完成 QQ 绑定后，可以在私聊中直接发送 UTF-8 编码的 `.txt` 文件，单个文件不超过 1 MiB；较大的书请分章发送。文件接收成功后会存入私人书房，收录过程不调用模型，也不会把整本原文塞入聊天记录。群聊和其他人的私聊不开放创建人的私人书房。

可以直接说“书架里有什么”“这本读到哪里了”“读一小段《书名》”或“给我看看《书名》的笔记”。也可以在本条消息里明确给出完整 HTTPS 网址，请她将该页正文收进书房；只导入当前页，不会自动抓取其他章节。通过聊天导入网址会使用正常的模型工具调用与回复额度。仅收录不代表已经阅读。

后台“书房”也支持 TXT 上传、单页在线导入、查看进度和移除书籍。自主阅读的节奏在设置中调整，需要服务保持运行及可用的模型 API；每次模型笔记输出最多 700 tokens，和聊天共用模型调用额度。聊天中要求“读一小段”也需要启用自主读书，并与定时阅读共用每日读书额度。读过的段落会推进阅读位置并留下笔记，未完成的请求不会算作已经读过。移除书籍会将其从书房移除并清空正文，已有笔记仍保留在记忆书架，可单独管理。

## 数据与恢复

`data\persona.sqlite` 存储所有本地数据，包括模型密钥和协议端配置；本机数据库未整体加密，应由操作系统账户和磁盘权限保护。不要把 `data` 上传 GitHub。`.gitignore` 已排除数据、备份、日志和依赖。

导出的备份文件经过加密。备份密码至少 12 位，遗失无法恢复。备份包含人格、记忆、事件、聊天、身份映射、书籍正文和阅读进度、上传和收藏的表情及删除记录，不导出设置中的模型密钥、QQ 密钥或后台登录密码；如果主动把秘密写进聊天或记忆正文，它仍属于备份内容。当前支持约 21 MiB 未加密 JSON、30 MiB 备份文件；书籍、上传与收藏图片也占用总备份容量。恢复到新机器需要重新初始化后台和配置接入。

同一实例已删除记忆的标记会保留，恢复较早备份不会复活这些记忆。旧备份本身仍可能包含旧内容；若将旧备份恢复到没有删除标记的全新实例，无法知道后来的删除操作。软删除也不等于彻底擦除原始聊天、事件和历史备份。

重新读取网页不会覆盖已有手工修订或恢复已删除的记忆 ID；但再次手动或定时阅读同一地址，仍可能新建包含相同原文的记忆。不希望再次收录的网页，应同时从定时阅读列表移除。重复阅读的经历原文仍会占用备份容量。

恢复会替换当前数据集，恢复前生成 `data\before-restore-*.pab`，使用本次输入的备份密码加密；恢复后 QQ、自主活动、固定网址阅读、自主读书、自主表达与自动备份暂停，核对数据后手动开启。所有跨平台账号绑定会清除，需重新验证，避免旧备份重新授予已撤销的身份权限。每次变更都有记录并不代表模型对事实的判断一定正确，应通过书架核对来源和修订。

自动备份在“身份与备份”中配置：默认间隔 6 小时、保留 30 个本地版本，服务运行期间才会执行，计算机休眠或关机时不会执行。备份先原子写入本地，启用 WebDAV 后才上传；回读 SHA256 一致才标记远端成功。远端失败保留本地版本并至少等待 15 分钟再重试。仅轮换本实例生成的本地备份，远端旧版本不自动删除。口令与 WebDAV 凭据保存在本机设置，不导出到备份；如果部署时生成了 `data/backup-recovery-key.txt`，请把这份恢复口令另行妥善保管。

WebDAV 目录需要预先创建，使用 HTTPS 地址、用户名和应用密码；本程序不会创建云盘账号。只配置本地备份时，文件不会同步到云端。`PERSONA_BACKUP_DIR` 可指定新实例的默认备份目录；已有实例应在后台修改已保存的目录。
