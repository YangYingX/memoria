# 栖忆 · Memoria

支持 Windows 与 Linux 部署的个人 AI 原型：同一个人格、按场合隔离的记忆，以及可核对来源的网页阅读。默认人格名为“未央”，可在后台修改。Windows 建议目录为 `D:\dev\persona-agent`。

公开项目名为“栖忆 · Memoria”，GitHub 仓库为 [YangYingX/memoria](https://github.com/YangYingX/memoria)。项目名与 AI 的人格名分别设置；本次更名保留已有安装目录、`persona-agent` 服务名、`PERSONA_*` 环境变量和备份格式，已有数据可继续使用。

## 本地启动

需要 Node.js 22.16 或更高版本。本机已使用 Node.js 22.22.1 安装依赖，无需 Python、Docker 或 GPU。Node 22 的 SQLite 模块会打印 experimental 提示。

- 双击 `start.cmd`：后台启动。打开 <http://127.0.0.1:3210>。
- 首次使用：打开 `data\setup-key.txt`，将初始化码粘贴到页面，设置至少 12 位的创建人密码。成功后初始化码文件自动删除。
- 双击 `stop.cmd`：停止本项目后台进程。
- 调试开发：先停止后台，再双击 `dev.cmd`；源文件修改会自动重启。Ctrl+C 停止。

手动运行：

```powershell
Set-Location D:\dev\persona-agent
npm.cmd ci --ignore-scripts
npm.cmd run dev
```

`npm.cmd run check` 检查 JavaScript 语法。调试时可在 PowerShell 中设置 `$env:PORT` 和 `$env:PERSONA_DATA_DIR` 使用独立端口和数据目录；双击启动脚本固定使用 3210 和项目内的 `data`。服务只监听本机，未设置开机自启。

Linux 安装依赖后执行 `bash scripts/start.sh` 后台启动、`bash scripts/stop.sh` 停止、`bash scripts/dev.sh` 开发调试。长期运行可安装 `deploy/persona-agent.service`。完整安装、数据目录、systemd 和远程 SSH 隧道说明见 [双平台部署文档](docs/deployment.md)。

## 先试什么

1. 在聊天页输入 `记住：我喜欢爵士乐`，再询问“我喜欢什么音乐”。未配置模型时，这是明确标记的离线演示，用来验证存储和检索。
2. 切换群聊调试场景，查询同样的话题：创建人的私密记忆不会进入群聊上下文。
3. 在记忆书架添加、修改、删除记忆，查看来源和修改历史。
4. 在阅读页输入公开文章网址。成功提取正文才写入阅读事件和记忆。
5. 在设置中填入模型 Base URL、模型名、API Key，保存后点击“测试模型连接”。留空 API Key 保留已有密钥；明确勾选清除才能回到演示模式。默认 DeepSeek 地址为 `https://api.deepseek.com`、模型 `deepseek-flash`，以非思考模式进行自然交流和工具调用；也支持提供 Chat Completions 和函数工具的其他兼容服务。普通聊天模型不支持工具时，需选择对应的工具模型。测试会产生一次短模型请求费用。
6. 导出加密备份，先预览再恢复；恢复前自动生成加密回滚文件。

## 当前能力与边界

- 创建人后台：本机初始化码、密码哈希、HttpOnly 会话；后台可以管理所有场合的记录。
- 统一人格：一个可编辑人格用于所有聊天。记忆可见范围在检索之前过滤。
- 记忆书架：原始事件、独立记忆、来源、修改历史、软删除标记；中文双字词/英文词检索。没有向量数据库或自动知识图谱。
- 模型工具：搜索当前场合记忆、按需翻阅记忆正文、保存记忆、阅读本次用户明确提供的完整公开网页网址。检索提供命中位置附近最多 1800 字的原文摘录；`read_memory` 每次读取最多 4000 字并返回后续位置，每次读取都会重新检查范围与删除状态。每次对话最多 4 轮模型调用、5 次工具调用；受剩余轮数限制，一次对话不保证读完整条长记忆。每日最多 200 次模型请求（UTC 日期）。网页访问限本次用户明确提供的完整网址，不会自行拼接网址或访问网页提供的新链接。成本仍由所用模型计费。
- 群聊调试：与创建人私聊使用不同历史和记忆。`public` 内容可被所有场合检索，发布前请确认内容适合公开。
- 网页阅读：HTTP/HTTPS 公共地址、正文提取、来源记录；限制重定向、超时和正文大小，拒绝本机及内网目标。一次提取最多 30000 字，已提取正文完整保存到经历记录与可检索书架；模型先获取节选，再按需搜索或翻阅其他位置。每次阅读保留独立经历；同一可见范围、来源网址、标题和正文均未变化时复用有效的书架记忆，避免重复条目占满召回结果。尚不支持登录态网站、脚本渲染页面、音视频理解。
- 定时阅读：按设置的网址列表轮流读取；默认关闭；5–1440 分钟间隔，每日 1–20 页，失败也计入预算（UTC 日期）。这是固定列表轮询，尚不是自主发现兴趣或自由浏览互联网。
- QQ：提供 OneBot v11 HTTP 事件入口和 HTTP 发送适配，以及登录/在线状态检测；默认关闭。真实 QQ 互通需单独安装、登录协议端并发送消息验证。
- 备份：手动导出/恢复与定期本地加密备份，可选 WebDAV 上传并回读校验。默认关闭，需配置备份口令；本地保留版本数与执行状态在后台可见。

## QQ 接入契约

协议端应与本服务运行在同一台机器，支持 OneBot v11 HTTP API 和带签名的 HTTP POST 事件。此仓库不包含 QQ 客户端或协议端，也不直接处理 QQ 密码。

1. 配置本地协议端的 HTTP API，例如 `http://127.0.0.1:3000`，并设置 Access Token。
2. 在后台填写机器人 QQ 号、HTTP API 地址和 Token，设置私聊/群聊白名单。
3. 协议端事件上报地址填写 `http://127.0.0.1:3210/integrations/onebot`。请求须包含 `X-Signature: sha1=<HMAC-SHA1(原始请求体, secret)>`。NapCat 的 HTTP 客户端 `token` 填入这里的 Webhook 签名密钥，HTTP 服务端 `token` 对应 Access Token；消息格式选择 `array`。本版使用双 HTTP，不需要 WebSocket。
4. 启用 QQ，在身份绑定页生成一次性验证码。创建人使用自己的 QQ 私聊机器人发送页面提供的 `绑定 ...` 命令，10 分钟内有效。
5. 创建人绑定后，QQ 私聊与本机创建人聊天共用历史。白名单内其他私聊分别隔离；白名单群聊仅在被 @ 时回复，即使创建人在群里说话也不加载其私聊记忆。

每个消息 ID 只处理一次。同一场合按收到顺序排队，最多 10 条；当前实现避免重复回复，但模型或发送失败后不会自动重发。处理失败会尝试回复提示，错误显示在事件记录中。后台绑定码只证明发送者掌握本机生成的验证码，不按昵称推断身份。各平台后续需要各自的身份验证适配。

“检测 QQ 协议端连接”只读取 `get_login_info` 与 `get_status`，确认登录账号匹配；它不发送消息，也不能代替签名上报、私聊和群聊的实际验收。[NapCat 安装说明](https://napneko.github.io/guide/boot/Shell)、[网络配置](https://napneko.github.io/config/basic)。

## 数据与恢复

`data\persona.sqlite` 存储所有本地数据，包括模型密钥和协议端配置；本机数据库未整体加密，应由操作系统账户和磁盘权限保护。不要把 `data` 上传 GitHub。`.gitignore` 已排除数据、备份、日志和依赖。

导出使用 scrypt 派生密钥与 AES-256-GCM 加密。备份密码至少 12 位，遗失无法恢复。备份包含人格、记忆、事件、聊天、身份映射和删除记录，不导出设置中的模型密钥、QQ 密钥或后台登录密码；如果主动把秘密写进聊天或记忆正文，它仍属于备份内容。当前支持约 21 MiB 未加密 JSON、30 MiB 备份文件，适合首版调试规模。恢复到新机器需要重新初始化后台和配置接入。

同一实例已删除记忆的标记会保留，恢复较早备份不会复活这些记忆。旧备份本身仍可能包含旧内容；若将旧备份恢复到没有删除标记的全新实例，无法知道后来的删除操作。软删除也不等于彻底擦除原始聊天、事件和历史备份。删除/隐私清理策略将在后续版本完善。

重新读取网页不会覆盖已有手工修订或恢复已删除的记忆 ID；但再次手动或定时阅读同一地址，仍可能新建包含相同原文的记忆。不希望再次收录的网页，应同时从定时阅读列表移除。重复阅读的经历原文仍会进入备份，本次去重不改变备份总容量上限。

恢复会替换当前数据集，恢复前生成 `data\before-restore-*.pab`，使用本次输入的备份密码加密；恢复后 QQ、定时阅读与自动备份暂停，核对数据后手动开启。所有跨平台账号绑定会清除，需重新验证，避免旧备份重新授予已撤销的身份权限。每次变更都有记录并不代表模型对事实的判断一定正确，应通过书架核对来源和修订。

自动备份在“身份与备份”中配置：默认间隔 6 小时、保留 30 个本地版本，服务运行期间才会执行，计算机休眠或关机时不会执行。备份先原子写入本地，启用 WebDAV 后才上传；回读 SHA256 一致才标记远端成功。远端失败保留本地版本并至少等待 15 分钟再重试。仅轮换本实例生成的本地备份，远端旧版本不自动删除。口令与 WebDAV 凭据保存在本机设置，不导出到备份；如果部署时生成了 `data/backup-recovery-key.txt`，请把这份恢复口令另行妥善保管。

WebDAV 目录需要预先创建，使用 HTTPS 地址、用户名和应用密码；本程序不会创建云盘账号。只配本地目录时不声称云端同步成功。`PERSONA_BACKUP_DIR` 可指定新实例的默认备份目录；已有实例应在后台修改已保存的目录。

## 开发结构

```text
src/server.js       本机 HTTP 服务、后台接口、QQ、定时阅读
src/agent.js        对话上下文、权限范围与模型工具循环
src/model.js        兼容模型 API、用量累计与连接检测
src/store.js        SQLite 数据、检索、修订和备份数据导入导出
src/reader.js       安全公开网页请求与正文提取
src/backup.js       加密备份格式
src/backup-jobs.js  定期本地版本与可选 WebDAV 回读校验
src/auth.js         密码与会话
public/            原生 HTML / CSS / JavaScript 管理界面
scripts/           启停与语法检查
```

当前核心为自行实现，运行时复用 Mozilla Readability 和 linkedom，许可证见 `THIRD_PARTY_NOTICES.md`。没有复制 MaiBot、AstrBot、NapCat 等框架的源码。项目使用 Apache-2.0 开源许可证。

DeepSeek 模型与参数依据 [当前官方 API 文档](https://api-docs.deepseek.com/) 配置；默认模型名称可能随提供方更新，后台可自行更换。
