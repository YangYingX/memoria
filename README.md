# 栖忆 · Memoria

一个拥有持续人格与长期记忆的 AI 伙伴。你可以管理她的人格、记忆和账号，让对话与阅读经历持续积累。项目正在开发中。

| 类别 | 当前支持 |
| --- | --- |
| 部署环境 | Windows、Linux |
| 聊天渠道 | QQ 私聊、群聊；可选飞书文本（实验接入）；本机管理后台 |
| 模型服务 | DeepSeek 等兼容 Chat Completions 与函数工具的 API |

默认人格名为“未央”，可在后台修改。项目名称与人格名称相互独立。

Memoria 由独立的 Node.js 服务运行，直接使用你配置的模型 API。关闭 Codex、开发工具或管理后台网页后，已启动的服务仍负责聊天、记忆、定时阅读与备份；活动需要部署机器和对应的平台接入保持运行。

## 安装与启动

需要 Node.js 22.16 或更高版本。下载仓库源码，解压后在项目目录安装依赖：

```bash
npm ci --ignore-scripts
```

Windows 使用 PowerShell 时可执行 `npm.cmd ci --ignore-scripts`。

使用小黑盒自主浏览前，还需要安装独立的 Chromium 阅读浏览器：

```bash
npm run browser:install
```

这会安装 Chromium headless shell，不使用你的日常浏览器账号。聊天中读取小黑盒公开帖子也需要这个浏览器。Windows PowerShell 可用 `npm.cmd run browser:install`；Linux 还需系统依赖，见[部署说明](docs/deployment.md#自主浏览器安装)。仅聊天和普通网页阅读不需要下载浏览器。

- **Windows**：双击 `start.cmd` 后台启动，核心进程异常退出后会退避恢复；双击 `stop.cmd` 同时停止核心与监管，不会因此重新拉起。可配置[当前用户登录后自动启动](docs/deployment.md#windows-安装与运行)。
- **Linux**：执行 `bash scripts/start.sh` 后台启动，执行 `bash scripts/stop.sh` 停止。
- 打开 [本机管理后台](http://127.0.0.1:3210)。首次使用时，填写 `data/setup-key.txt` 中的初始化码并设置至少 12 位的管理密码。

服务器安装、独立数据目录、systemd 和远程访问方法见 [安装与部署说明](docs/deployment.md)。

## 开始使用

后台主要用于首次配置、查看记录和管理数据。完成模型配置与创建人 QQ 绑定后，日常交流、收书、询问阅读进度和笔记都可以在 QQ 私聊中进行。

创建人私聊还可以说“最近读了什么、发了什么？今天还剩多少次？”查询实际活动记录；说“现在去小黑盒逛一下”触发一篇未读帖子的阅读与读后笔记；在自主浏览来源启用 B站后，也可说“现在去B站逛一下”，让她发现未读候选并尝试取得文字、写笔记。说“核对一下最近的小黑盒帖子”回读本人最近已提交的帖子。普通私聊和群聊不开放这些活动工具。

1. 在聊天页输入 `记住：我喜欢爵士乐`，再询问“我喜欢什么音乐”。未配置模型时，这是明确标记的离线演示，用来验证存储和检索。
2. 切换群聊调试场景，查询同样的话题：创建人的私密记忆不会进入群聊上下文。
3. 在记忆书架添加、修改、删除记忆，查看来源和修改历史。
4. 在阅读页输入公开文章网址。成功提取正文才写入阅读事件和记忆。
5. 在设置中填入模型 Base URL、模型名、API Key，保存后点击“测试模型连接”。留空 API Key 保留已有密钥；明确勾选清除才能回到演示模式。默认 DeepSeek 地址为 `https://api.deepseek.com`、模型 `deepseek-flash`，以非思考模式进行自然交流和工具调用；也支持提供 Chat Completions 和函数工具的其他兼容服务。普通聊天模型不支持工具时，需选择对应的工具模型。测试会产生一次短模型请求费用。
6. 导出加密备份，先预览再恢复；恢复前自动生成加密回滚文件。

## 当前能力与边界

- 创建人后台：通过密码访问，可管理人格、账号和所有场合的记录。
- 统一人格：在不同聊天场合使用同一人格设定，并按场合调用有权访问的记忆。
- 记忆书架：查看和搜索记忆、核对时间与来源、修改内容或删除条目，并保留修订记录。聊天与 DSH 的搜索结果可分页继续翻查，每页最多 6 条，同一主题的旧记录不会只因排在第 7 条以后就无法取得索引；正文和原话仍按需分段读取。
- 私聊书架线索：模型对话时，还会从当前私聊书架的“人物”“兴趣”各补充最多 2 条标题索引，帮助在本条消息没有相关关键词时延续旧话题。索引只列部分条目，具体内容需按需核对正文与原话；转述或引用中的偏好需要区分主体。群聊和公开场合不加载这份私聊背景。
- 历史对话档案：书架没有收录的聊天细节，也可按需搜索并分段核对，不受最近 16 条消息的短期上下文限制。用户原话和助手旧回复分别标明，助手旧话不作为用户事实。旧版记录只要保留明确、有效的消息与回复关联，也可检索；缺少关联或未完成的轮次不猜测配对。
- 主动私聊回忆：已确认发送给创建人的主动私聊，也可在离开近期上下文后按时间、关键词搜索和核对，例如“你上周主动对我说过什么”。记录只包含她当时的原话，不虚构用户回应；来源已失效的内容不再提供。旧记录缺少可靠确认或平台证明时存在检索限制，见[历史主动私聊](docs/deployment.md#历史主动私聊)。
- DSH 只读接入：独立插件宿主从栖忆书架检索、分页读取记忆及来源，不以 DSH 会话存储长期记忆。聊天、阅读页或固定网址计划中的完整 B站 BV 视频链接可触发字幕取稿；全文按顺序分段保存，保留时间戳和覆盖限制。B站自主阅读笔记使用 DSH 原生模型接口，由栖忆提供统一人格、模型调用额度和长期保存；无需给插件填写模型密钥。可在本机独立浏览器登录 B站专用账号，或用项目附带的 Chrome 登录桥导入已有 B站登录，也可匿名读取；实际可用性取决于平台认证和字幕。尚不读取画面、音频或发布内容。所有场合共用每日默认 6 次的读取尝试额度，后台可设为 0–50；配置见[部署说明](docs/deployment.md#dsh-只读插件接入)。
- 记忆子代理：启用 DSH 后，聊天可按需交给一个真实的 DSH agent 回合，搜索旧记忆和对话档案、继续翻页并核对正文和原话，例如“让记忆子代理核对一下最早提过的约定”。子代理只使用当前场合有权读取的资料；人格、身份、模型历史和每次工具授权仍由栖忆管理。每轮聊天最多尝试一次，最多额外 4 次模型请求和 5 次只读工具，与每日模型总额度共用；不占 B站读取或公开发布次数。任务结束销毁临时会话，下次仍从栖忆检索，不依赖该会话继续存在。子代理实际引用的记忆、原话或分段索引被更正、删除或变得不可见时，本次结果会停止使用；来源核对延续到使用该结果的聊天回复保存之前。已经发起的模型请求仍计入额度，不自动重试。
- 创建人聊天优先：同时处理的聊天场景仍最多 3 路。占满时，QQ、飞书创建人私聊可等待最多 30 秒取得下一空位，并优先于新来的普通会话；在途聊天继续处理。飞书会优先选择已入队且尚未开始的创建人私聊，同类消息保持原顺序。等待不跳过身份、渠道和模型额度校验，已预留的渠道次数不退回。
- 私聊与后台任务：创建人当前私聊实际调用 DSH 记忆或表情时，可取消正在占用 DSH 的自动阅读、笔记、心情或主动拟聊任务，最多等待 5 秒退出并清理后再运行。已有手动读取和其他前台 DSH 任务不被抢占；未及时退出时不会并行启动。普通书架与历史分页检索、当前表情目录仍可使用。取消不退回已用次数，已经保存的原阅读保留，未完成笔记不保存，不自动重试。
- 聊天纠错：明确要求更正或忘记一条记忆时，可先核对原条目，再在同一条目上修订或将其移出书架；保留修改记录，并按发言者与当前场合核对权限。成功后给出简短确认并结束本轮，不复述条目正文或附带表情；其他问题请另发消息。
- 在途回复：本轮实际使用的近期聊天、书架索引或检索来源在生成或发送前被更正、忘记或变得不可见时，停止尚未发出的回答；QQ 分段回复也会在每段发送前核对。正常新增消息和无关记录修改不因此取消回复；已经在途或发出的内容无法保证撤回。

- 旧图片聊天：超过近期上下文后，仍可用“图片”“附件”检索有可靠来源的附图对话，并核对当时的图片数量、原话和文字回复。数量来自保存时一致的消息与来源记录，缺少证明或记录有冲突时不提供图片标记。历史图片不作为新的视觉输入；以后只能依据当时留下的文字观察回答，助手旧话仍可能有误。
- 对话与记忆：模型可以检索和保存当前场合的记忆，并按需阅读本次直接分享的完整公开网址；支持单独发链接或说“帮我看看这个链接”。明确禁止阅读、仅引用的命令、示例或未来打算不作为当次阅读要求，程序会在调用前核对。一次对话不保证读完整条长记忆。每日模型请求上限默认 3000，可在“人格与设置 → 对话模型”调整为 1–1000000 的整数，按 UTC 日期计数，费用由模型服务商收取。
- 陪伴额度预留：在“人格与设置 → 对话模型”调整“创建人私聊预留请求数”，默认 20，可设为 0–200 的整数，0 关闭。预留包含在每日模型总额中；按默认总额 3000 和预留 20，普通任务共用前 2980 次，最后 20 次仅供创建人当前私聊及其同轮 DSH 记忆检索。实际预留不超过总额。群聊、其他私聊和她主动发起的聊天不使用预留；一次聊天可能需要多次请求，仍受渠道与并发等限制，详见[模型额度与私聊预留](docs/deployment.md#模型额度与私聊预留)。
- 人物归属：对话记忆会附上可核对的来源发言者，聊天中也可以要求查看原话。发言者不一定是内容谈论的人；转述、指代和后续修订需要分别判断。原话仅在对应记忆仍有效且两者都属于当前可见范围时提供，不通过公开摘要读取私人聊天。
- 延续阅读话题：聊天时提供当前场合有权访问的最近 3 条阅读索引，涵盖成功获取正文的网页和完成笔记的书籍片段。模型可以按需翻阅正文、查找相关的旧兴趣，再决定是否自然提起；索引本身不含正文，也不保证每次问候都会聊阅读。删除对应书架记忆后，该条不再进入索引。
- 群聊调试：与创建人私聊使用不同历史和记忆。`public` 内容可被所有场合检索，发布前请确认内容适合公开。
- 网页阅读：HTTP/HTTPS 公共地址、正文提取、来源记录；限制重定向、超时和正文大小，拒绝本机及内网目标。一次提取最多 30000 字，已提取正文完整保存到经历记录与可检索书架；模型先获取节选，再按需搜索或翻阅其他位置。每次阅读保留独立经历；同一可见范围、来源网址、标题和正文均未变化时复用有效的书架记忆。普通网页阅读器提取 HTML 或纯文本；聊天、后台阅读和自主浏览中的小黑盒公开帖子使用同一个独立浏览器，当前支持 `/app/bbs/link/数字帖子号` 地址。超过提取上限会标记截断，不代表读完整个网页。当前不支持登录态访问及音视频理解。
- 固定网址阅读：按设置的网址列表轮流读取；默认关闭；5–1440 分钟间隔，每日 1–20 页，失败也计入预算（UTC 日期）。
- 自主浏览：支持小黑盒公开社区与通过 DSH 发现 B站热门视频，来源可选一个或两个。默认关闭，初始来源仍为小黑盒；开启后默认在 `Asia/Shanghai` 时区的 09:00–23:00 内每天随机安排合计 3–6 次尝试，按兴趣选择未读资料。B站每次从最多三条热门候选中按配置话题、人格关键词与未读记录挑选一条；发现和取稿合计计一次 DSH 额度。次数、时区、活跃时段和兴趣可调整；失败也计入额度，成功取得正文或字幕文字才留下阅读记忆，并可写读后笔记。它与固定网址阅读分别设置。
- 聊天兴趣选题：有模型时，小黑盒自主浏览也会参考创建人私聊中近期、来源可核对的兴趣记忆。每次最多一次模型判断，计入后台设置的每日模型总额度；没有合格记忆、无法调用模型或判断不可靠时，继续按配置话题与人格选择。模型需区分本人喜好、转述、否定和后续修订，但相关性仍可能误判。只使用最多 12 条完整记忆及原话，总长度受限；不等于完整兴趣画像。修改或删除相关记录后重新判断，在途判断所依赖的记录变化会取消本次活动。私人内容只发往你配置的模型服务，不发送给小黑盒，也不写进自主活动日志；日志保留所参考记忆的 ID。此功能不自动向其他人推送帖子。
- 读书：创建人可以在 QQ 私聊或后台上传 TXT、EPUB，也可导入单个 HTTPS 网页正文，保存阅读进度和笔记。EPUB 按书中声明的阅读顺序提取本地文字，不保留图片与排版，不支持正文加密、扫描图片书或远程章节。自主读书默认关闭；开启后默认每天最多 2 次，每次约 3000 字符，随机安排在 `Asia/Shanghai` 的 09:00–23:00。聊天中也可以查询书架、进度、笔记，或指定一本书读一小段。QQ 收书保留已验证的原私聊来源，后续主动聊书仍须满足主动私聊开关、时段与额度；收书确认取得有效发送回执后才进入助手聊天档案，确认消息发送失败不撤销已经收好的书。
- QQ：支持私聊、群聊及图文消息。需另行安装并登录 OneBot v11 协议端，在后台配置账号和白名单；默认关闭。识图需要所选模型支持视觉输入。
- QQ 连发文字：默认等候 700 毫秒，将同一人在同一私聊或群里的最多 3 条连续纯文字合成一次回复，合计最多 8000 字符、最长等待 1800 毫秒。后台可调整为 0–1500 毫秒，0 关闭合并。图片、引用、收书、绑定命令及不同群友的发言会分开处理；群聊默认只处理 @，也可按下述设置关注普通群消息。合并一批计一次 QQ 聊天尝试，模型请求仍逐次计数。原消息来源随对话保存；处理途中身份或 QQ、模型、人格配置变化会取消尚未完成的回复，已发起的请求仍计次，已在途的发送无法保证撤回。
- QQ 引用与点名：聊天会区分当前发言者、@ 对象与已核对的引用原话。仅尝试读取同一群或当前私聊对方的消息；无法核对时标为缺失，不猜测内容。引用原话最多保留 1200 字符，随历史对话保存，可检索并核对原发言者；引用的旧图片仅保留数量标记，不自动识图。引用和 @ 不改变身份或记忆权限，引用里的操作用语不作为新的执行要求。
- QQ 普通群聊：可在白名单群内按概率关注未 @ 的普通消息，模型仍可保持安静。“普通群消息关注概率（%）”默认 0，可设为 0–100；“同群自主关注间隔（秒）”默认 300，可设为 60–3600。抽中即占用本群间隔，安静或失败不退回，@ 回复不受这项间隔限制。未抽中的消息不处理、不下载图片；已处理内容沿用本群记忆范围，不意味着保存全部群聊，也不读取创建人的私聊。关注判断共用 QQ 智能对话额度，实际模型请求共用后台设置的每日模型总额度。
- QQ 回复节奏：可选“分段发送聊天回复”和“最长回复停顿（毫秒）”，默认关闭分段、停顿为 0，保持单条立即发送。停顿上限可设为 0–5000 毫秒，非 0 时按文字长短与少许随机变化；发送前及段间每次均不超过此上限。开启分段后只按已有自然空行分为最多 3 段，含代码围栏保持整条，文字合计最多 5000 字符，表情仅随最后一段发送。不增加模型调用，也不影响绑定、收书、错误确认或主动私聊。失败、结果未确认时停止余段且不重发；未确认发出的尾段不写入回复历史或备份，已发前段无法撤回。取消范围见[部署说明](docs/deployment.md#回复节奏与部分发送)。
- 表情：附带 60 张内置人设主题的透明背景表情，包含中文文字和日常情绪。模型根据语气选择，每次最多一张。创建人可上传自有图片供各聊天场合选用；从 QQ 对话自主收藏的表情仅在原私聊或原群复用，均可在后台查看、删除。可选用固定版 `dsh-meme` 的关键词检索模块，想配图时按需找候选，不再每轮注入全部图库说明；配置见[部署说明](docs/deployment.md#可选表情关键词检索)。
- 心境：对话、自主表达和主动私聊使用同一份持久状态，随时间自然回稳。可开启间歇评估：默认每 180 分钟最多一次、每天最多 4 次，有新资料才调用；每次只看一个聊天场合或一份已读公开资料。对话可选择已适配的原版 `dsh-feiyu-mood`，执行其回合结束钩子与变化算法；公开阅读保留 DSH 原生评估。每次最多一次模型请求，栖忆核对置信度、来源和状态后保存。群聊和公开表达只使用数值与固定情绪标签，不携带私人原因。状态随加密备份迁移，设置见[部署说明](docs/deployment.md#心情与节奏)。
- 自主表达：开启后可在配置的时段内选择安静，或执行已允许的 QQ 空间动态、签名、头像、小黑盒发帖与评论回复，以及 B站视频评论通知回复。发帖、评论和回复默认全平台合计每天最多 80 次，可在后台自定义 0–100，并分别设置平台上限。表达欲、间隔及各项动作均可调整；QQ 需要协议端支持，小黑盒表达目前需要 Windows 专用 MuMu 设备，B站回复需要另配独立社交宿主，默认关闭。
- 主动私聊：默认关闭，可在设置中允许她向已验证的创建人 QQ 或飞书原私聊主动聊天。原渠道不可用时保持安静，不改投其他平台。优先从近期最新私聊延续近况，也可分享实际读过的片段；没有这些新线索时，可核对书架中来源有效的旧主题。未启用 DSH 时使用内建拟聊，已启用时沿用插件运行层；两者共用人格、书架、额度与发送检查。可选 Mate 内核提供好奇、疲劳与交流节奏建议。主动聊天欲、每日上限、机会间隔、聊天后安静期和活跃时段均可调整。
- 飞书文本：可选的原版 `dsh-im` 连接，支持获准私聊和群内 @ 后回复原消息，沿用统一人格和分场合书架。聊天额度独立于 QQ；默认关闭，应用凭据需在本机配置。目前完成本地模拟平台联调，真实账号需部署后验证，见[飞书接入说明](docs/feishu.md)。
- 绘图 API：目前只提供服务地址、模型、密钥和额度的预留配置，尚不发起绘图请求；内置表情已随程序提供。
- 备份：手动导出/恢复与定期本地加密备份，可选 WebDAV 上传并回读校验。默认关闭，需配置备份口令；本地保留版本数与执行状态在后台可见。

## QQ 接入

协议端应与本服务运行在同一台机器，支持 OneBot v11 HTTP API 和带签名的 HTTP POST 事件。此仓库不包含 QQ 客户端或协议端，也不直接处理 QQ 密码。

1. 配置本地协议端的 HTTP API，例如 `http://127.0.0.1:3000`，并设置 Access Token。
2. 在后台填写机器人 QQ 号、HTTP API 地址和 Token，设置私聊/群聊白名单。
3. 协议端事件上报地址填写 `http://127.0.0.1:3210/integrations/onebot`。NapCat 的 HTTP 客户端 `token` 填入这里的 Webhook 签名密钥，HTTP 服务端 `token` 对应 Access Token；消息格式选择 `array`。本版使用双 HTTP，不需要 WebSocket。
4. 启用 QQ，在身份绑定页生成一次性验证码。创建人使用自己的 QQ 私聊机器人发送页面提供的 `绑定 ...` 命令，10 分钟内有效。
5. 创建人绑定后，QQ 私聊与本机创建人聊天共用历史。白名单内其他私聊分别隔离；白名单群聊默认只在被 @ 时处理，可在 QQ 设置中开启普通群消息的概率关注。即使创建人在群里说话，也不加载其私聊记忆。

QQ 的“每日智能对话尝试上限”默认 200，可在后台设为 0–1000。私聊、群聊与主动私聊判断共用，按 UTC 日期计数；在处理前预留，处理或发送失败、主动选择安静也计次。设为 0 或用尽后保持安静，不积压补发；身份绑定和 TXT、EPUB 收书仍可使用。重启、修改设置或在原机器恢复备份不会清零当天已用次数。本机后台聊天不占这项额度，仍受模型总额度约束。

此额度与每日模型请求、公开发布额度分别计数。一次智能对话可能需要多轮模型请求，因此模型总额度可能先用尽；聊天中可询问今日 QQ 对话和公开表达剩余额度。

普通聊天中，被长度限制等原因中断的模型响应不会触发其中的操作，也不作为完整回答存档；先前已完成的操作保留，已经发起的请求仍计次，不自动续写。模型或消息发送失败后不会自动重发，可在后台查看错误后重新发送。请妥善保管一次性绑定命令，只由创建人本人发送。

创建人可在“身份与备份”登记自己的小黑盒数字 ID，或用已经绑定的创建人 QQ 私聊发送 `绑定小黑盒 <数字ID>`。这是创建人本人指定的账号关联，不是小黑盒登录验证；与栖忆专用账号分开保存，随加密备份导出，解绑后不再作为当前身份资料。账号列表只用于创建人私聊，不提供给公开表达模型。

B站也可在同一页面登记本人的数字 UID，或在已验证的创建人 QQ 私聊发送 `绑定B站 <数字UID>`（也接受 `绑定哔哩哔哩 <数字UID>`）。登记时会拦截当前已保存的栖忆 B站执行账号；未保存执行账号时，仅按创建人提供的标识记录。此关联不验证 B站登录，不开启评论回复或扩大公开线程权限；解绑仍在“身份与备份”操作。

“检测 QQ 协议端连接”检查登录与在线状态，不发送消息。配置完成后，请分别通过私聊和群聊发送消息，确认能收到回复。[NapCat 安装说明](https://napneko.github.io/guide/boot/Shell)、[网络配置](https://napneko.github.io/config/basic)。

### 主动找创建人聊天

可在创建人私聊中明确开启，或在“人格与设置 → 主动私聊”中开启。她向已验证的创建人 QQ 或飞书原私聊发送，先核对到期约定；其余随机话题优先考虑最新私聊，也可以分享实际阅读、延续旧主题或保持安静。默认每天最多尝试发送 1 次，机会间隔至少 360 分钟，在 `Asia/Shanghai` 的 10:00–22:00 内安排；与你私聊后至少等待 60 分钟，后台创建人对话也计入这段安静期。

她优先从最近七天内仍可见且未判断过的创建人最新私聊出发，按需检索并核对近况、旧兴趣或旧约定，再决定是否自然聊一句。未启用 DSH 时由内建回合调用已配置的模型 API；已启用时使用 DSH 回合。两条路径都最多 4 次模型请求、5 次只读工具，可分页核对书架和旧对话，不要求近期先有新阅读；不访问平台、读取新网页或自行发送。同一机会只判断一种话题；选择安静、失败或取消后，不转而生成阅读分享。没有新的私聊线索且未选用旧主题时，仍可考虑实际阅读；每次最多调用模型一次，接收人格、一个实际读过的片段和最多 6 条近期私聊文字。没有自然话题、对方表示不想聊或证据不足时，应选择安静。

随机话题与约定跟进共用每天最多 6 次判断，与普通聊天共用后台设置的每日模型总额度，并占原渠道的智能对话额度；一次拟聊回合只占一次原渠道智能对话尝试。没有有效的原渠道绑定、连接或可用来源时不调用。随机话题中的每条最新私聊、同一网页地址、同一已读书籍片段或旧主题条目的同一版本均只判断一次，安静、失败或取消也不自动重试；同网址重读产生新条目也不会重新判断。发起原渠道发送后，失败、结果未确认也占发送次数，不自动重发。同一实例恢复较旧备份会保留当天已用的主动判断和发送计数；判断记录随备份迁移，新机器无法从判断前的旧备份得知后续发生过的判断。

QQ 主动拟聊前会先核对协议端在线且登录账号匹配。未通过的候选不消耗判断、模型或 QQ 智能对话额度，也不将话题记为已判断或增加约定判断次数。存在多条到期约定时，会按顺序寻找原渠道就绪且有额度的一条；较早约定不可用不会堵住其他独立约定，也不会把它改投别的平台。每个机会最多判断一条，开始判断后保持安静、失败或取消均不再换题。全部不可用时等待原有机会间隔，不在恢复连接后立即补发；真正发送前仍再次核对，已经执行的模型判断仍计次。

后台可查看下次随机机会、今日发送尝试和最近结果。关闭、解绑、配置或所用资料变化、收到创建人新私聊时，会取消尚未发起的消息；已经在途的消息无法保证撤回。发送始终由栖忆在核对账号和额度后执行，DSH 不持有发送权限。内建拟聊无需安装 DSH；启用 DSH 后，默认使用其原生 agent 接口，也可按[部署说明](docs/deployment.md#dsh-只读插件接入)选择已适配的原版 `dsh-speak-up`。DSH 配置或运行异常不会自动切换内建回合，也不会因此重新判断同一话题。

主动私聊的近期背景沿用聊天来源屏蔽，已撤回来源及引用它的旧回复不会再次进入生成；生成后保存来源关联，便于后续撤回。已核对的 QQ 引用也随近期交流和旧主题提供，区分引用者、原发言者与旧助手回复的对象，正文节选会标注。心情评估保留有限的发言者与引用依据，引用中的偏好或情绪不直接归给当前对方。真实的新私聊仍会触发安静期，不因其内容被屏蔽而提前搭话。

未启用 Mate 时，没有新的私聊线索或可分享的阅读，也可核对书架中仍有真实来源的旧兴趣或公开资料，由当前拟聊引擎决定是否自然聊一句。旧记录不是今天的新任务。自上次创建人私聊后已有一次主动发送尝试时，这条旧主题补充路径保持安静，直到创建人再次私聊；发送失败或结果未确认也按已尝试处理，不催回复。

创建人在私聊中更正记忆后，当前版本可按新的更正原话和原渠道成为主动话题候选；旧出处仍保留为历史。后台手动编辑的当前正文仍可检索，但不会凭空取得新的发送来源。后续再更正、删除或原渠道失效会停止旧候选；旧版审计和恢复的备份不自动获得该关联。详见[更正后的记忆与主动话题](docs/deployment.md#更正后的记忆与主动话题)。

可按[部署说明](docs/deployment.md#可选-mate-陪伴节奏内核)安装原版 Mate 数值内核，默认关闭。它只在现有随机机会中运行本机算法，不另起定时器、不调用模型、不复制人格或建立第二份文本记忆。启用后沿用内核的好奇、疲劳与未回应退避建议，在最新私聊之后、阅读分享之前考虑旧主题；内核出错时保持安静。到期约定仍优先，既有开关、安静期和额度不变。

后台“主动私聊”显示可选内核状态，并提供“重置陪伴节奏”用于恢复损坏的数值状态或过多的未处理历史。重置不删除书架、清空发送或未回应记录，也不会开启任何开关。这里的数值是交流节奏参数，不表示真实主观感受。

### 聊天调整主动陪伴

创建人也可在自己的私聊中直接调整主动陪伴，例如“先别主动找我”“可以主动找我聊天了”“主动聊天每天最多2次”“主动聊天欲调到50”“主动聊天间隔改成120分钟”。只保存本条明确给出的开关、聊天欲、每日上限或间隔，沿用后台的范围限制；频率调整不顺带开启，恢复不改变表达欲、每日上限或间隔。可以问“主动聊天现在是什么设置”。不带时长的暂停持续到明确恢复；“今天别”“明天再开启”等时间不明确或将来定时要求会先澄清。群聊、他人转述、引用和图片不能授权这些更改。

主动联系的时段也可以在聊天中调整，例如“主动聊天时段改成19点到23点”或“主动私聊时段设为9点到22点”。使用 24 小时制整数，开始时间为 0–23 点，结束时间为 1–24 点，开始须早于结束；当前支持同一天内的时段。查询“主动聊天时段是什么设置”会显示两端时间和当前时区，时区仍由后台配置。修改时段只保存明确的起止时间，不自动开启主动私聊，也不清空已用次数、修改免打扰或立即发送；之后仍按原有空闲期、间隔和额度决定是否开口。

临时需要安静时，可说“先别主动找我两小时”或“暂停主动私聊30分钟”，支持整数 1–1440 分钟或 1–24 小时。成功设置后开始计时，重启仍保留期限；到期继续遵守原开关、时段、空闲和额度，不保证立即开口。说“结束主动私聊免打扰”只清除期限；明确恢复主动私聊会同时清除期限并开启原开关。再次明确设置期限会从本次应用时重新计时。普通聊天仍可回复，详见[临时免打扰](docs/deployment.md#临时免打扰)。

这份偏好同时用于创建人的 QQ 与飞书主动私聊，不清空已用次数、未回应记录或已有约定，也不改变各渠道开关和公开表达额度。保存成功才表示已调整；仍需满足账号、连接、模型、时段、空闲与预算条件，不保证立即发送。

### 聊天中的跟进约定

QQ 与飞书共用同一人格、书架及主动陪伴日程，消息保留可核对的原私聊来源。升级后先在要使用的渠道发一条新消息；缺少来源标识的旧聊天不会被猜成某个平台。飞书的真实应用权限仍需部署后验证，见[飞书接入说明](docs/feishu.md#主动私聊与约定跟进)。

创建人可在已验证身份的 QQ 或飞书私人对话中，用纯文字明确提出未来的跟进，例如“明晚20:00问问我考试情况”；按“主动聊天时区”解释时间，也可以明确说明时区。时间或目标不清楚时先询问，不从图片、引用或旧话推断新授权。跟进发往提出约定的原私聊，不发到群、其他人的账号或另一平台。飞书需要本机仍保留经核对的原始入站来源，并连接支持主动回执的原版宿主；尚需部署者验证真实应用权限。

可以说“列出我的约定”“暂停考试提醒”“恢复考试提醒”或“取消考试提醒”。暂停保留约定和原时间，可在仍有效时明确恢复；取消会结束约定，之后不能恢复。暂停不延长截止时间，也不清空已用次数。恢复备份后，QQ 先重新绑定，再明确恢复仍有效的暂停条目；已取消、过期或失效的条目不能恢复。飞书本机收件执行记录不随备份迁移，新实例应在重新验证后的原私聊中重新明确约定。后台“主动私聊”只展示约定标题、状态、跟进起点和截止时间，操作仍通过聊天进行。

一次约定保存在统一记忆书架，可设在一分钟后至 366 天内，最多保留 20 条未结束约定。到期后优先考虑跟进，仍需满足主动私聊开关、活跃时段、冷却、空闲、账号、模型与额度条件；默认关闭，聊天欲设为 0 也保持安静，保存约定不会自行开启。它是机会式关心，不是准点闹钟。每条最多判断 3 次，安静、失败或取消也计次；到期后 24 小时截止，不集中补发。

跟进与随机主动聊天共用每日最多 6 次判断、默认最多 1 次发送，以及原渠道智能对话和后台设置的每日模型总额度，不另增额度。关联约定记忆或原始来源被更正、忘记，或账号解绑后，旧约定会失效。已经发起发送但结果未确认时标为“未确认”，不自动重发。此调度由栖忆保存与执行，可选原版 `dsh-speak-up` 负责当次拟聊；没有接入另一套常驻约定调度器。

### 图片与表情

QQ 私聊可以直接发图片或附上问题；群聊可 @ 机器人，开启普通群消息关注后也可由她自主选择处理。支持 JPEG、PNG、WebP、GIF，每条消息最多 4 张、单张不超过 8 MiB、合计不超过 20 MiB。协议端必须提供可下载的公开图片地址。私聊或 @ 消息处理图片失败时会提示；自主关注失败则保持安静，原因可在后台查看。识图结论可能有误，可在对话中纠正。

普通图片仅在当轮传给模型，默认不保留原图和临时下载地址。后续对话可以参考先前的文字回复，不能据此重新查看原图；需要核对细节时请重发。要求她记住图片中的内容时，保存的是带来源的文字观察。

创建人可在后台“表情库”上传自有图片，并填写名称和适用情境。管理员上传的图片可供所有聊天场合选择，请只上传愿意在这些场合使用的内容。

她也可以自行收藏适合反复使用的表情包、梗图，每轮最多一张；普通照片、自拍、聊天截图、文档和无法确定的图片不应收藏。QQ 收藏不跨私聊对象、群或平台复用，即使多个账号属于同一个创建人也如此。后台可核对来源和删除。

上传与收藏图片均保存在本机私有数据中，并纳入加密备份，不会上传到项目 GitHub。单张上限 2 MiB，上传与收藏合计最多 8 MiB、64 张；同一 QQ 私聊或群的收藏最多 20 张。内置表情不占这些额度。

### 聊天中的自主活动开关

0.3.58 起，创建人可在自己的已验证私聊中说“暂停自主浏览”“恢复自主读书”“暂停公开表达”或“开启公开表达”，也可询问“当前自主活动开关是什么”。明确要求同时调整多个总开关时，会一并保存；引用、转述、图片文字、群聊及其他人的请求不会授权更改。

这些操作与后台共用自主浏览、读书和公开表达的三个总开关，保留时段、兴趣、单个平台及动作开关和已用额度。暂停公开表达也会暂停自主签名与头像等动作；仅要求停某个平台或发动态时，需要明确范围，不能据此关闭全部表达。恢复后按原计划和条件执行，不保证立即行动，也不自动开启原先关闭的平台。已经在途的发布无法保证撤回；限时或将来的要求会先说明当前只支持立即切换，不会自动到时恢复。

创建人还可在已验证私聊中说“暂停B站回复”或“恢复B站回复”，也支持“哔哩哔哩视频评论通知回复”。此操作只同时关闭或开启 B站平台及通知回复两个配置开关，不改公开表达总开关、其他平台、发布额度或登录态。它只影响已接入的视频评论回复通知，不开启私信、动态或主动新评论；缺少总开关或社交登录态时仍不会执行。可询问“B站回复现在开着吗”查看配置；时段、表达欲及已有用量继续生效。

创建人还可在 QQ 私聊中说“公开表达欲调到50”“公开表达每天最多20次”“公开表达间隔改成120分钟”，或询问“公开表达现在是什么设置”。表达欲接受 0–100 的整数；每日次数是全平台发帖、评论、回复的合计上限，接受 0–100；机会间隔接受 60–1440 分钟，也可用 1–24 个整小时。表达欲不是必须发言的比例，机会到来时仍可保持安静。

只保存本条明确给出的值，可与明确的总开关要求一起调整。修改数值不顺带开启表达、平台或动作，不改变时段、今日已用次数和原有日界，也不立即发布。降低上限不会清空已用次数；签名、头像继续遵守自身限制，合计次数设为 0 不等于关闭它们，完全暂停请说“暂停公开表达”。各平台上限和模型总额度仍生效；引用、群聊、图片、含糊或将来定时要求不能授权更改。

### 小黑盒自主浏览

安装阅读浏览器后，在后台“自主活动”中设置兴趣、次数与活跃时段并启用。可查看下一次安排、最近结果，也可手动发起一次浏览。活动需要服务保持运行；休眠或关机期间不会执行，恢复后不会集中补跑所有错过的次数。

创建人在私聊中要求现在浏览时，会使用同一个阅读任务，消耗当天原定机会，仍检查启用状态、今日次数和其他任务；手动请求可以在计划时段外执行。正文读取和读后笔记分别记录结果；失败、没有新帖子也计入尝试次数。每轮聊天最多尝试一次社区浏览或帖子核对。纯查询活动不会发起浏览，也不会改变计划或额度。

帖子核对目前需要 Windows 专用 MuMu 设备保持运行。它只回读最近已记录为成功或待审核的小黑盒帖子，核对本人账号、唯一标题与完整正文，不重发、不修改额度；记录核对时的显示状态，不保证所有访客都可见。若最近一次提交结果未知且缺少可靠正文，暂不核对，也不会用旧成功帖子代替。未核对到不代表帖子已删除或被拒绝。活动查询会区分历史提交记录与后续核对时间。

小黑盒公开帖子列表由独立浏览器匿名获取，正文也优先匿名读取。Windows 上已配置、启动并登录专用 MuMu 设备时，网页正文失败可改由项目调用客户端正常阅读入口，核对账号和公开列表标题后提取支持的图文帖与文章文字；不使用创建人本人的小黑盒账号。不自动处理验证码；两种入口都失败时不会记为已读。客户端读取会标记为局部摘录，不代表读过图片、视频或未显示内容。每日次数是尝试额度，不保证每次都能读到帖子。成功阅读的记录默认供创建人使用。

选下一篇小黑盒帖子时，可以延续自己旧公开笔记中“还想了解”的问题。有模型且存在有效依据时，最多调用一次选文判断，参考创建人明确表达的近期兴趣，以及最多三条公开阅读的旧笔记（每条最多 800 字符），在本次最多 40 个未读候选中选择。她自己的疑问与创建人的偏好分别记录，不能混为一谈；没有可靠相关项或判断失败时，沿用配置关键词与同分随机选择。选择相关帖子只表示值得继续了解，不表示问题已经解答。B站选片继续按配置兴趣和人格关键词进行。

B站选片若明确返回无可读文字，一次浏览机会内最多再选择一个不同的未读视频；最多尝试两个，每次都计入 DSH 每日阅读尝试上限，无须额外模型选片。平台限制、网络错误、额度不足和资料校验失败时直接停止。无可读文字的候选保留 24 小时冷却，即使后一个视频读取成功也不会立即再选前一个；只有实际取得且核对过的文字才保存阅读经历。

旧笔记和对应原阅读都须保持未修改、未删除；修改后再恢复相同正文也不作为连续阅读的依据。选文期间依据变化时取消该次活动，已用尝试仍计数。兴趣和笔记只交给已配置的模型判断，不发送给社区平台；活动次数、原有随机日程和模型总额度保持不变。

已配置模型时，每次成功自主阅读后最多再调用一次模型，整理原文要点、自己的想法和待了解的问题。小黑盒和 B站的读后笔记都可参考最多三条有效的公开阅读旧笔记，每条最多 800 字符，延续或修正以前的想法；不额外调用模型整理背景，也不把旧观点当作新事实。笔记与原帖分别存入记忆书架，保留来源和实际阅读记录，聊天时可检索；笔记不代表已证实的事实，也不会自动改写人格设定。生成失败仍保留原阅读，不自动重试，调用计入每日模型总额度。公开表达只参考公开小黑盒帖子的原始阅读、未改动笔记与最近已确认的本人小黑盒动态，不加载创建人账号或私聊。

Windows 本机还可配置[小黑盒专用安卓设备](docs/android.md)。项目通过 MuMu 官方管理工具和 Android 接口管理设备、核对账号、读取公开图文文字，并可设置昵称签名与初始头像。在“人格与设置 → 自主表达”中开启小黑盒，再分别选择发帖、评论或回复，默认不启用该平台。发帖需要准确分区名；评论和回复需要 Google Android CLI 与 SDK Platform Tools。服务会按表达欲、时段和间隔自行选择表达方式，每个平台每次机会最多执行一种公开表达。

同一设置区可打开小黑盒专用浏览器登录窗口，正常登录并完成平台验证后，点击“完成登录与验证，保存状态”。Windows 使用本机 Google Chrome；Linux 需要图形桌面，并先运行 `npx playwright install chromium` 安装完整 Chromium。若已绑定专用 MuMu 账号，保存时会核对账号一致。浏览器登录与创建人的账号绑定分别管理；登录状态只保存在本机，不进入记忆备份，也不会自动开启自主表达。保存成功不代表平台认证一直有效，遇到登录或验证提示时需重新确认。

评论与回复默认关闭。开启后，服务会重新打开最近实际读过的公开帖子，核对标题和最多六条可见主评论。模型只能回应该帖或选择已经核对的评论标识；正文最多 200 字，不能自行指定其他网址或作者。目前不展开全部评论，也不在楼中楼内继续回复。发送前核对引用对象和输入全文；发送后只有在对应评论区域回读到本人昵称及完整文字才确认成功。平台界面或排序变化可能使回执无法确认，此时计次并停止当天该平台后续公开表达，避免重复提交。

B站接入支持别人回复专用账号视频评论，以及在视频评论中 @ 专用账号产生的通知。配置[独立社交宿主](docs/deployment.md#b站视频评论通知回复)并保存社交凭据后，在“自主表达”中分别开启 B站和“回复视频评论通知”；默认均关闭。表达机会内最多核对 20 条通知，只考虑七天内可核验的视频评论回复或 @，可自然回应或保持安静；不处理私信、动态，也不主动新发评论。同一条评论通过不同通知到达时只处理一次。当前线程与公开记忆可延续交流，创建人私聊和其他群聊不进入这组背景。回复正文最多 200 字，模型不能更改账号、视频或目标评论。

0.3.57 起，B站回复可按需搜索、翻页和核对当前评论线程及公开书架的旧记忆与已完成对话，初始片段以外的资料也有机会被找到。每次判断最多 4 次模型请求、5 次只读工具，与每日模型总额度共用；工具不能访问其他线程或私人书架，也不能发布内容。生成或发送前所用资料发生更正、删除或屏蔽时，本次回复停止；已提交的内容无法保证撤回。检索有步数和正文上限，不保证一次找完整个档案。

同一评论楼里的近期发言和旧对话保留发言者关联，模型可据此区分不同人的经历和偏好；同名账号分别处理，同一账号改昵称仍可关联原记录。此关联只用于当前公开线程，不提供创建人私聊权限；缺少可靠标识的旧记录不推断为当前评论者的经历。

同一通知在判断后保持安静、失败、取消或发送结果未确认，都不自动重试。平台返回回复编号只表示取得提交回执，不保证通过审核或已对其他人可见。B站与 QQ、小黑盒使用同一自主表达任务和全平台额度，另有自己的可调上限，不新增另一套不受表达欲、时段和间隔约束的发布流程。Chrome 登录桥需升级并重新加载至 1.1.0，再点一次导入；原来只保存阅读凭据的文件仍可读字幕，不能据此认定可以社交回复。

发帖、评论与回复共用全平台每天最多 80 次的默认额度，可自定义为 0–100；每个平台还受自己的上限约束。80 是上限，不是必须完成的数量，默认 360 分钟间隔和 45% 表达欲会让实际次数更少。普通公开表达每次机会最多调用一次模型，B站通知回复可在上述检索预算内继续核对；每天最多判断 `max(6, 每天公开表达总上限)` 次，与聊天共用每日模型额度。发布失败、未确认结果也计次，修改设置不会清零当天记录。

表达前先检查平台接入：QQ 核对在线状态和机器人账号，小黑盒核对专用设备已启动且应用已安装，不会为此自动启动模拟器。平台不可用时跳过本次机会，不为该平台调用表达模型或增加发送次数；其他可用平台仍可继续。实际提交前再次检查，提交阶段的失败或未知结果仍按尝试计次。错过的机会不集中补发。

小黑盒发布前核对专用账号、标题、正文和所选分区；只操作可核验的项目草稿，遇到其他草稿时保留并停止。点击发布前写入本机记录，随后从帖子页核对标题、作者昵称和完整正文；少量文字被平台替换为星号时会标记变化，并展示实际正文，其他差异不予确认。“内容审核中”记为已提交待审核，不代表已向其他人公开。结果不明时不自动重试，也暂停该平台当天后续动态。平台审核、登录失效、界面变化或验证码可能阻止发布，后台会保留实际结果。项目不自动处理验证码。

QQ、小黑盒已确认的发帖、评论与回复，以及已提交待审核的动态会保存到记忆书架，注明当时状态并关联经历记录；评论与回复保留原帖来源。记录默认仅创建人可见，聊天时可检索，随加密备份导出。B站取得回复编号后，将对方原评论、来源及已回复状态保存到当前线程书架；自己的完整回复保留在带来源关联的对话档案，沿用资料更正与遗忘的过滤规则。后续公开表达可参考最近三篇已确认的本人小黑盒动态，延续观点或选择安静，减少重复分享。

### 通过聊天收书与读书

创建人完成 QQ 绑定后，可以在私聊中直接发送 `.txt` 或 `.epub` 文件；TXT 使用 UTF-8 编码。单个文件不超过 3 MiB，提取后的文字不超过 3 MiB、100 万字符；超过任一上限请分章发送。书房最多保存 10 本，正文合计不超过 5 MiB。文件接收成功后会存入私人书房，收录过程不调用模型，也不会把整本原文塞入聊天记录。群聊和其他人的私聊不开放创建人的私人书房。

EPUB 支持常见的本地文字电子书，按书中声明的阅读顺序收录。后台填写的书名优先，否则使用电子书内的书名，缺少时使用文件名。原 EPUB、图片、公式、字体和排版不保存；纯图片扫描书、正文加密、缺章或不支持的远程／SVG 正文会导入失败，不保存部分书。归档限 2048 项、声明解压总量 16 MiB，超限可转换为 TXT 或分章导入。导入完成只表示文字已存入书房，之后才按阅读任务分段处理并记录进度。

可以直接说“书架里有什么”“这本读到哪里了”“读一小段《书名》”或“给我看看《书名》的笔记”。也可以在本条消息里明确给出完整 HTTPS 网址，请她将该页正文收进书房；只导入当前页，不会自动抓取其他章节。通过聊天导入网址会使用正常的模型工具调用与回复额度。仅收录不代表已经阅读。

收书、继续阅读需要本条消息中的明确请求。引用、代码、否定、将来打算、单独发网址，或只询问进度、已有笔记时，不会推进阅读或导入。网址请用空格、括号或换行与说明文字分开；读书目标按本轮书房列表核对，未说清书名且有多本候选时，需要先选定一本。一轮阅读与导入合计最多尝试一次，失败也计入。

后台“书房”也支持 TXT、EPUB 上传、单页在线导入、查看进度和移除书籍。网址导入仍只读取当前网页，不直接下载 EPUB 或追读其他章节。自主阅读的节奏在设置中调整，需要服务保持运行及可用的模型 API；每次模型笔记输出最多 700 tokens，和聊天共用模型调用额度。聊天中要求“读一小段”无需开启自主读书；手动与定时阅读共用每日读书额度和单次长度，手动阅读可以在活跃时段之外进行。读过的段落会推进阅读位置并留下笔记，未完成的请求不会算作已经读过。移除书籍会将其从书房移除并清空正文，已有笔记仍保留在记忆书架，可单独管理。

聊天中明确要求读指定书时，若自主读书正在进行且仍有当天读书额度，会先取消该后台阅读，最多等待 2 秒让它结束，再读指定书。未及时结束时返回忙碌，不并行另读；已有手动或聊天阅读不会被抢占。取消的阅读尝试及已发出的模型调用仍计次，未完成的旧笔记不会保存或推进进度。

继续读同一本书时，会参考最多三条此前已读片段的有效旧笔记，每条最多 1000 字符，帮助延续疑问或修正看法；仍只调用一次模型。只使用有实际阅读记录且从未修改、尚未删除的笔记，不混入别的书或私人聊天。生成期间相关笔记被修改、删除或书籍进度变化时，本次结果不保存、进度不推进，已用尝试不退回。旧笔记不是原文，也不表示她能同时记住整本书。

0.3.46 起，新生成的读书笔记、网页读后思考会保存实际使用的旧笔记关联。更正或忘记来源时，依赖旧版本且尚未人工修订的后续笔记也会移出书架，停止参与后续阅读与聊天；阅读进度和原始经历保留。人工更正过的笔记正文保留。旧版没有记录的关联无法补推，不保证自动识别其中的派生内容。

### 私聊的空闲记忆整理

0.3.56 起，栖忆可以在空闲时从新的私聊原话中挑选值得留下的人物、经历或兴趣，保存到同一记忆书架。默认开启，每隔至少 3 小时尝试一次、每天最多 4 次，且所选私聊最近 10 分钟没有新消息；可在“人格与设置”中关闭，或调整间隔及每日上限。每次只整理同一个私聊，最多保存两条完整原话，保留发言者和出处，不自动改写旧记忆或创建提醒。助手回复失败时，已经收到的有效用户原话仍可能被整理。

首次开启只处理之后的新聊天，不追溯旧档案；重启不会重新开始，关闭后再开启则从新的位置继续。图片、群聊和明确的记忆管理指令不参与自动整理；已经收录、修改或忘记过的同一来源不再收录。失败、取消或选择保持安静也会记为本次尝试，不自动重试这批原话。整理与聊天共用每日模型额度；原话可能包含引用、猜测或指令，保存不代表其中内容已经核实。恢复备份后此功能暂停，核对后重新开启。

### 通过聊天更正与忘记

可以在私聊中说“更正记忆：我现在更喜欢古典乐，不再喜欢爵士乐”，或“忘掉我喜欢爵士乐这条记忆”。她会先定位和核对条目，再调用更正或移除工具；每轮合计最多尝试处理一条。更正保留原 ID、来源、分类、可见范围和旧版本；聊天更正要求原条目与新正文均不超过 4000 字，较长条目在后台编辑。记录在核对后发生变化时，本轮不再覆盖它。

明确纠正旧记忆时，需要更新原条目；未找到或更正失败时，不会改用新增记忆保存一份矛盾副本。否定、引用中的旧记忆操作也不会因此获得另存权限；这项检查不能识别所有换句话说的重复事实。

创建人在自己的私聊中可管理私人书架；其他私聊及群聊仅能处理由当前发言者原话形成的同场合记忆。可阅读的公开记忆不因此获得修改权限。引用和转述中的操作用语不应当作更改要求，目标不清时应说明具体内容再处理。模型仍可能误解意图，可在后台核对修订和经历记录。

引用段落、未闭合代码块中的“更正”或“忘记”不会授权修改；需要执行时，请在引用外另起一段明确提出。聊天查看或新读出的书籍笔记也会关联到本轮回复，相关笔记更正或忘记后，不再从旧回复继续引用旧内容。

可以问“昨天我们聊到哪里了”“上周提过什么”，或指定日期回想旧聊天。0.3.49 起，对话检索支持按原话的日期定位，再分页核对内容；日期沿用后台“主动私聊”的时区，默认 `Asia/Shanghai`。创建人在已验证身份的各平台私聊共用可见档案，其他场合沿用各自可见范围。助手已失效的旧回复继续隐藏，检索到的原话仍须按当时发言者和时间理解。

0.3.50 起，还可以问“昨天在 QQ 聊过什么”，将日期和平台一起定位。当前支持区分创建人的 QQ、飞书私聊，依据已保存的来源记录归类；正文提到平台名不会改变聊天归属。缺少或冲突的旧来源保持未知，仍可不限定平台检索。解绑或恢复备份后，完整历史来源的标签仍可保留，实际接入及发送继续核对当前账号和连接。

“忘记”会停止在记忆书架中检索该条，并留下删除标记，防止本实例恢复旧备份时将它重新放回书架；原始聊天、经历、修订和已有备份仍可能包含旧内容，不等于彻底擦除。更改与删除记录随加密备份迁移。

修订或忘记对话来源的书架记忆后，其关联原轮次也会停止进入历史档案检索和模型近期历史；引用了该记忆或已屏蔽轮次的助手旧回复会被隐藏，相关轮次中独立的用户原话仍可核对。这按记录关联判断，不能识别所有换句话说或独立重复的同一事实；有效记忆的来源核对仍可用于比较原话与修订。原始数据未因此擦除。

0.3.48 起，新保存的聊天、主动私聊和 B站评论回复关联实际参考的记忆版本，涵盖普通记忆、网页阅读和笔记。更正后，引用旧版本的回复不再进入后续模型历史；新回复仍可使用更正后的正文。仅参考独立用户原话时，不会因同一旧轮次的助手内容已失效而一并隐藏。旧回复只有条目关联、没有版本记录时，有已知修订便保守隐藏，无法补推没有保存的依赖。

自主表达生成期间也会核对实际参考的阅读、笔记和本人动态。来源更正或删除后停止发送；如果提交后才失效，保留已经提交的结果记录，但不把失效正文另存成可供新一轮引用的书架记忆。这不会撤回平台上已实际发布的内容。

## 数据与恢复

`data\persona.sqlite` 存储所有本地数据，包括模型密钥和协议端配置；本机数据库未整体加密，应由操作系统账户和磁盘权限保护。不要把 `data` 上传 GitHub。`.gitignore` 已排除数据、备份、日志和依赖。

导出的备份文件经过加密。备份密码至少 12 位，遗失无法恢复。备份包含人格、记忆、事件、聊天、身份映射、书籍正文和阅读进度、聊天约定、上传和收藏的表情及删除记录，不导出设置中的模型密钥、QQ 密钥或后台登录密码；如果主动把秘密写进聊天或记忆正文，它仍属于备份内容。恢复到新机器需要重新初始化后台和配置接入。

0.3.65 起，备份先 gzip 压缩，再使用 AES-256-GCM 加密，支持最多 128 MiB 原始 JSON 和 30 MiB 加密文件；两项限制均须满足，实际容量取决于压缩率，书籍和图片也占用容量。超限会明确失败，不会裁剪记忆。手动导出、自动备份和恢复前快照使用同一格式。新备份须使用 0.3.65 或兼容的更新版本恢复；仍可读取此前未压缩的备份，数据结构版本保持 5。

恢复还会检查记录格式，单类最多 10 万条、合计最多 25 万条；压缩不取消这些限制，预览显示数量不代表全部记录已通过恢复校验。生成和恢复大备份会短暂占用较多内存，并暂停处理本机其他请求，请等待完成。

0.3.33 导出数据结构版本 5，新增聊天约定；仍可导入结构版本 1–4 的旧备份。版本 4 起包含对话来源屏蔽记录。恢复旧备份会保留本实例已有的来源屏蔽；它不保证保留所有后来修订的正文，恢复仍会替换当前数据集。版本 5 备份须使用 0.3.33 或兼容的更新版本恢复；含超过 1 MiB 单本书籍的备份须使用 0.3.43 或兼容的更新版本恢复，含新笔记关联及保留的阅读修订证据时须使用 0.3.46 或兼容的更新版本恢复。

含通用记忆版本关联或保留的普通记忆修订证据时，须使用 0.3.48 或兼容的更新版本恢复。本机已知的各类修订证据会随恢复保留，即使旧备份尚无对应条目；恢复仍替换当前正文，不会自动合并所有新正文。全新实例只能依据导入备份中的证据，无法知道备份之后发生的更正。

同一实例已删除记忆的标记会保留，恢复较早备份不会复活这些记忆。旧备份本身仍可能包含旧内容；若将旧备份恢复到没有删除标记的全新实例，无法知道后来的删除操作。软删除也不等于彻底擦除原始聊天、事件和历史备份。

重新读取网页不会覆盖已有手工修订或恢复已删除的记忆 ID；但再次手动或定时阅读同一地址，仍可能新建包含相同原文的记忆。不希望再次收录的网页，应同时从定时阅读列表移除。重复阅读的经历原文仍会占用备份容量。

恢复会替换当前数据集，恢复前生成 `data\before-restore-*.pab`，使用本次输入的备份密码加密；恢复后 QQ、自主活动、固定网址阅读、自主读书、自主表达、主动私聊、空闲记忆整理与自动备份暂停，核对数据后手动开启。所有跨平台账号绑定会清除，需重新验证，避免旧备份重新授予已撤销的身份权限。未发送且仍有效的聊天约定会暂停，重新绑定 QQ 后还需在聊天中明确恢复；已尝试但结果未确认的约定不重发。每次变更都有记录并不代表模型对事实的判断一定正确，应通过书架核对来源和修订。

自动备份在“身份与备份”中配置：默认间隔 6 小时、保留 30 个本地版本，服务运行期间才会执行，计算机休眠或关机时不会执行。备份先原子写入本地，启用 WebDAV 后才上传；回读 SHA256 一致才标记远端成功。远端失败保留本地版本并至少等待 15 分钟再重试。仅轮换本实例生成的本地备份，远端旧版本不自动删除。口令与 WebDAV 凭据保存在本机设置，不导出到备份；如果部署时生成了 `data/backup-recovery-key.txt`，请把这份恢复口令另行妥善保管。

WebDAV 目录需要预先创建，使用 HTTPS 地址、用户名和应用密码；本程序不会创建云盘账号。只配置本地备份时，文件不会同步到云端。`PERSONA_BACKUP_DIR` 可指定新实例的默认备份目录；已有实例应在后台修改已保存的目录。
